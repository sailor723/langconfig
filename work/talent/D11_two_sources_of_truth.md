# 决定项 D11：岗位要求的权威在哪一边 —— 公理，还是 `requirement` 表？

> 这是目前唯一一个拦在 apply 之前、且**不能由我决定**的架构问题。
> 下面每个数字都是在本机实测出来的，不是估计。

---

## 1. 问题是什么

岗位要求现在同时存在于两个地方，而**两者各自都能独立判定"谁合格"**：

| | 公理（`reasoning.ttl`） | `requirement` 表 |
|---|---|---|
| 形态 | `:matches_<岗位> ≡ :Candidate ⊓ ∃hasSkill.:skillsFor_<岗位> ⊓ ∃yearsExperience[≥N] ⊓ ∃educationRank[≥M]`<br>其中 `:skillsFor_X ≡ :Cat1 ⊔ :Cat2 ⊔ …`（类别 OR） | 31 行（26 essential + 5 desirable），每行带 `kind` / `tier` / `threshold` / `verbatim` / 零件列表 |
| 判定方式 | HermiT 蕴含 | 覆盖率 ≥ 0.5 + 年限/学历作评分 |
| 决定什么 | **成员资格** | **评分与闸门** |
| 出处 | 无 | 每行带 JD 原话与文件名 |
| 能否表达"读不到 ≠ 不合格" | ❌ | ✅（unknowns / completeness） |
| 能否表达复合要求与阈值 | ❌ | ✅ |
| 能否被门禁重算 | ✅（`check_abox_sync` 逐行） | ✅（`fit_component` 逐行） |

## 2. 实测：两个裁判只在 13% 上一致

同一个 `talent_db`、同一批 277 份简历：

| 岗位 | 仅技能 OR（必要条件） | 现行公理 | 评分闸门 | **公理 ∩ 闸门** |
|---|---|---|---|---|
| 专案工程师 | 78 | 25 | 14 | **1** |
| 业务助理 | 54 | 20 | 55 | **5** |
| 业务跟单 | 175 | 48 | 37 | **10** |
| 人资专员 | 138 | 0 | 8 | **0** |
| 关务报关员 | 32 | 0 | 7 | **0** |
| 副总助理 | 137 | 35 | 55 | **12** |
| 品质经理 | 114 | 25 | 0 | **0** |
| 工程文员 | 198 | 0 | 55 | **0** |
| 招聘专员 | 97 | 31 | 13 | **4** |
| 管理课长 | 97 | 20 | 55 | **6** |
| **合计（跨岗）** | **1120** | **204** | **299** | **38** |

**公理给 204，闸门给 299，交集只有 38 —— 一致率 13%。**

差异的来源是可列举的，不是噪声：
- **年限/学历**：公理把它们当硬门槛（挡掉 129 无年限 + 71 无学历），闸门按 D10 把它们移出成员判定 → 公理里 166 人不被闸门接受
- **技能语义**：公理是"类别 OR"（很松），闸门是"每条复合要求覆盖率 ≥ 0.5"（多零件要求更严）→ 闸门里 261 人不被公理接受
- **人资专员/工程文员**：公理 0 人而闸门 8/55 人 —— 因为这两个岗位的 JD **没有声明年限门槛**，而公理里仍然带年限 facet，等于替客户发明了一条门槛

## 3. 三个选项

### 选项 A — 公理唯一权威（`requirement` 表降级为"证据与措辞"）
- 名单 = HermiT 的蕴含结果；`requirement` 表只用来渲染理由、存 JD 原话
- ✅ 单一计算路径，`check_abox_sync` 已经是现成的门禁
- ❌ 表达不了复合覆盖率、阈值、tier、以及**"读不到 ≠ 不合格"**
- ❌ 每次改词表/阈值都是改 TBox + 重推理；那 10 条不可评估要求永远无法诚实表达
- ❌ 等于把 `requirement` 表整个废弃——本轮做的工作作废

### 选项 B — `requirement` 表唯一权威（公理只保留类结构）
- 名单 = 覆盖率闸门；`:matches_*` 定义停止参与判定
- ✅ 复合/阈值/tier/unknown 都能表达；改动是数据编辑不是本体编辑
- ❌ 推理机不再是裁判，`check_abox` / `check_abox_sync` 对名单变成摆设
- ❌ 本体的意义被掏空——"这份 CV 到底算不算这个岗位"退化成一个 SQL 条件

### 选项 C — 分层：公理判"能不能"，`requirement` 判"够不够"（**推荐**）

| 问题 | 归公理 | 归 requirement 表 |
|---|---|---|
| 是不是这个岗位的候选人（**必要条件**） | ✅ `∃hasSkill.(该岗位要求的类别)` —— 开放世界里"至少会一项相关技能"正是 OR 能表达的 | |
| 复合要求满足几成、门槛 0.5 | | ✅ 覆盖率 |
| 哪条必须、哪条优先 | | ✅ tier（有 JD「优先」字样才降级） |
| 年限 / 学历 | | ✅ 评分项（D10：退出成员判定） |
| "读不到" vs "不合格" | | ✅ unknowns / completeness |
| 技能家族近似（D9） | ✅ 类层级给 family | ✅ 给具体分值 |

判定顺序：**公理是入口（必要条件）→ requirement 闸门是闸 → 两者皆过才算 qualified。分歧必须显式报出，不许一方默默盖掉另一方。**

**改造成本很小**：公理只需要**删掉 `∃yearsExperience` 与 `∃educationRank` 两个 facet**，`∃hasSkill.(类别 OR)` 保留原样——因为它本来就是一条必要条件，不是门槛。

实测这条路的后果：

| 岗位 | C：必要条件 ∩ 闸门 | 现行：公理 ∩ 闸门 | 变化 |
|---|---|---|---|
| 专案工程师 | 14 | 1 | +13 |
| 业务助理 | 13 | 5 | +8 |
| 业务跟单 | 26 | 10 | +16 |
| 人资专员 | 8 | 0 | +8 |
| 关务报关员 | 7 | 0 | +7 |
| 副总助理 | 55 | 12 | +43 |
| 品质经理 | 0 | 0 | 0 |
| 工程文员 | 55 | 0 | +55 |
| 招聘专员 | 13 | 4 | +9 |
| 管理课长 | 22 | 6 | +16 |
| **合计** | **213** | **38** | **+175** |

品质经理仍然是 0（**语料里没有品质专才**，与模型无关——见 `stage_extended_vocab.md` §4）。

## 4. 我推荐 C，并给出三条理由

1. **每一层做它擅长的事**：描述逻辑擅长表达开放世界的**必要条件**（"必须至少会一项相关技能"），不擅长表达"满足六成"；关系代数擅长后者。硬让一方干另一方的活，就是现在这 13% 一致率的来源。
2. **它保住了门禁**：`check_abox_sync` 继续有意义（公理层可被逐行重算），`fit_component` 也可被逐行重算。选项 B 会让两个门禁对名单失效。
3. **它把"不可评估"变成一等公民**：10 条抽不出来的要求，在 C 里如实标为 `assessable=false` 并在名单上显示"差哪一项"，而不是像 A 那样只能判成"不合格"。

## 5. 选 C 之后必须一并确定的三件小事

1. **分歧如何披露**：公理说合格而闸门说不够（或相反）时，名单上要不要单独一栏？我建议要——这正是 D6"被排除的人必须可见"的同一原则。
2. **`reasoning.ttl` 里 4 个"没有 JD"的岗位**（行政专员/技术经理主管/设计工程师/实验室技术员，共 54 人）在公理里本来就不存在 `:matches_*`，C 下保持拒绝，不生成。
3. **`role.required_years` 为 NULL 的岗位**（人资专员、工程文员、关务报关员）在公理 facet 删除后自然处理正确——现在它们被一条客户没声明的年限门槛挡成 0 人，这是 C 顺带修掉的 bug。

## 6. 待你决定

- **选 A / B / C**（我推荐 C）
- 若选 C：是否同意**从公理里删掉 `:yearsExperience` 与 `:educationRank` 两个 facet**（这是 C 的唯一必要改动，且是对 D10 的直接落实）

定了之后，apply 的顺序是：改公理 → `materialize.py`（活库）→ `check_abox_sync` 应绿 → `apply(confirmed=True)`。

# C 落地之后:实际行为、代价、未解决问题

> 这一节是 C **apply 之后**补的。上面那部分是"选 C 的理由",这里是"选了 C 之后系统到底怎么动"。

## 一、C 之后的判定是四步

```
① 公理入口     谁是候选池?          ∃hasSkill.(该岗类别) → 638 条蕴含
② 闸门         每条可评估要求达标?   覆盖率 ≥ 0.5,全过才算 qualified → 299 人
③ 评分         分数/完整度/缺口      fit_component 逐项贡献 → 731 行排序
④ 披露         两个裁判分歧          v_axiom_vs_gate → 每条都能解释
```

第 ④ 步的实测分布(2026-11-19):

| verdict | 行数 | 含义 |
|---|---|---|
agree_rejected | 1862 | 两边都说不过 |
axiom_only | **609** | 推理说"可能胜任",复合要求没达标 |
gate_only | **156** | 复合要求达标,推理推不出来 |
agree_qualified | **143** | 两边都同意 → 一致率 48% |

**`gate_only` 的 156 行有确定原因**:人资专员、工程文员、关务报关员 **三个岗位没有公理**(它们的 JD 没写年限门槛,`author_tbox` 当年跳过)。有闸门、无公理 → 全落这一格。

## 二、C 为什么能救回 129 个人 —— 量化解释

OWL 的世界观里**没有"不知道"这一档**,只有"是"和"不是"。所以 C 之前:

| 情况 | 公理(OWL)判定 | 闸门判定 |
|---|---|---|
年限未知(129 人) | **不合格**(没有断言就不满足存在量词) | **未知**(不计入分母,标 completeness) |
学历未知(71 人) | 不合格 | 未知 |
技能全无(18 人) | 不合格 | 未知 |

**实测佐证**(2026-11-19 做的对照实验):

```
AND 年龄+学历+年限 于公理 → qualifies_副总助理 = 1 人
只用闸门(不 AND)        → qualified = 55 人
```

原因是三个字段的**联合覆盖只有 0.4%**(1/277):age 39%、education 74%、years 53%,但缺失分布在**不同**的简历上。

**C 把这些稀疏字段移出公理,正是为了避免"未知"被吞成"不合格"。**

## 三、C 的三条代价(必须承认)

**代价 1 · 本体的判定力被主动削弱。** `:matches_*` 从"够不够格"降为"有没有相关技能"的一道粗筛。看起来变弱,但原来那个"强"是靠把未知当不合格换来的假象。

**代价 2 · 推理不再是终审,而是一票。** `check_abox_sync` 保证"表 = 重新推理的结果",但它保证的是**技能层的蕴含**,不是名单正确性。名单正确性由 `fit_component` 保证。两个门禁、两个职责。

**代价 3 · 分歧要一直维护。** 156 + 609 行是**长期的**;每次改词表或阈值,这两个数字都会动。没人看,披露视图就是摆设。

## 四、C 没有解决的问题(不假装解决了)

| 未解决 | 具体 | 影响 |
|---|---|---|
**三个岗位没有公理** | 人资专员、工程文员、关务报关员:JD 未写年限门槛,`author_tbox` 跳过 | `gate_only` 156 行无法收敛 |
**A 维度(性别/年龄)在 C 的分工之外** | C 只切了"技能 vs 其余",没管人口属性 | 两边都没进 |
**覆盖率闸门天然粗糙** | `composite` 只有 2–4 个部件 → 覆盖率只有 0/0.33/0.5/0.67/1 | 区分度受限(N2) |
**"完整度优先"排序未最终确认** | 同为满分时信息完整者排前 | 名单顶部顺序(O4) |
**一个岗位常只有 1–2 条可评估要求** | 副总助理只有 Office 一条可判 | 55 人"合格"的实际含义是"55 人会 Office" |

**这五条的落地清单在 `score_models.yaml`** —— 那里把每一个分数(谁算、分母是什么、能跟谁比、不能拿来干什么)写成可执行的门禁,并用 `scripts/talent/check_score_models.py` 实跑。C 的代价 3 说"分歧要一直维护",那个文件就是维护的手段:609/156 这类数字写死在门禁里,漂了会红。

## 五、C 的边界条件:什么时候该重新考虑

C 成立的前提是**数据稀疏**。当覆盖改善到某个点,年限/学历可以搬回公理:

| 指标 | 现在 | 搬回公理的阈值 |
|---|---|---|
age 覆盖 | 39% | > 90% |
education 覆盖 | 74% | > 95% |
years 覆盖 | 53% | > 90% |
**三者联合覆盖** | **0.4%** | **> 80%** |

**C 是"数据不足时的正确架构",不是永久妥协。** 数据成熟后公理可以承担更多 —— 这是一条可随数据演进的路。

## 六、一句话

> C 不是"用表替代本体",而是承认两件事各有强弱:本体强在**必然性**(会不会、能否组合、谁包含谁),表强在**程度**(多少、多完整、排第几)。C 让每件事只有一个主人,并强制分歧可见。
>
> 代价是本体从"终审法官"降为"一道闸门",换来 13% → 48% 的一致率,以及 129 个"年限未知"的人不再被当成不合格。
