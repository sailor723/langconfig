# 同一个 JD,两种判法:本体+join vs 只有 LLM

JD:**品质经理** · 候选人 **10** 人 · 要求 **10** 条 · 模型 `deepseek-chat`(temperature 0)· 每人跑 **2** 遍

> 两边读的是**同一份材料**(简历 OCR 原文 + 一面记录)。差别只有一处:
> 一边先把材料拆成数据项、再按组件/属性的比较语义 join 出判定;
> 另一边把原文和判据一起塞进 prompt,让它直接说结论。

## 一、可测的四件事

| 指标 | 结果 | 怎么读 |
|---|---|---|
| 判定一致率 | **33/90 = 37%** | 两种做法在「都能判」的格子上的一致程度 |

| LLM 自一致性 | **98/100 = 98%** | 同 prompt 同温度跑 2 遍,结论是否完全一样 |

## 四、分歧不是噪声:它们分成几类

逐格看 57 条分歧没意义,按「谁让了步」归类之后,它们的形状很清楚:

| 分歧模式 | 格数 | 该怎么读 |
|---|---|---|
| 本体有结论 / LLM 退未知 | **41** | LLM 不敢对「材料里没写」下结论。**不是它错**,是它把举证责任都放在一次生成里;本体敢下,是因为抽取阶段已经用封闭词表把「读过了,没有」定死了 |
| 本体说不满足 / LLM 说满足(组件类) | **10** | **本体的词表没覆盖到同义表达**。这类要点开原文看:多数情况 LLM 是对的,本体该补词表 |
| 本体说满足 / LLM 说不满足(属性类) | **2** | 阈值口径或组件粒度问题。这类要人裁 —— 两边都能自圆其说时,以客户原文为准 |
| LLM 有结论 / 本体未知 | **2** | 本体缺数据项(抽取没读到),LLM 从上下文补出来了 —— 可回填 |
| 本体说满足 / LLM 说不满足(组件类) | **1** | 同上,看原文 |
| 本体说不满足 / LLM 说满足(属性类) | **1** | 同上,看原文 |

## 五、这份对比能说明什么、不能说明什么

**能说明的**:

- 一致率:两种做法在这批人上的重合程度。分歧集中在哪几条要求,表里逐条列了。
- 自一致性:同一个模型同温度跑 2 遍,2% 的格子上结论会变。本体侧不存在这一项 —— 同输入必同结论,是可以拿来做门禁的。
- 引文可核验:LLM 引的原文里有 1 处**在材料里找不到**。找不到的引文,对外就是不可复核的断言。
- 成本:LLM 每人每次数秒、按量计费;本体侧判定是毫秒级纯计算,重算不花钱。

**不能说明的**:

- 不能说明谁「更准」。这批人谁合格,只有真面过的 HR 和用人经理知道。
- 不能拿这一次的一致率外推到别的 JD。样本是 10 人 × 10 条,分歧集中在阈值为数值的要求上时,换一份阈值不同的 JD,一致率会变。

## 六、结论

如果一致率很高,LLM 可以拿来**做交叉复核**:本体判完,让 LLM 独立判一遍,不一致的格子推给人看。它不适合**替代**判定,原因不是「模型笨」,而是:

1. 判定要能被复算 —— 半年后有人问「这个人当时为什么判不满足」,   答案要在文件里,不能是「上次模型这么说的」;
2. 判定要能当门禁 —— 自一致性不满 100% 的东西,没法做成 gate;
3. 「未知」要能保真 —— 一旦模型把「没读到」写成「不满足」,就是在凭空判一批人不合格,而这种错在报告里看不出来。
