# 只改 prompt,LLM 能追平本体吗

JD:**品质经理** · 候选人 **10** 人 · 要求 **10** 条 · 模型 `deepseek-chat`(temperature 0)· 每档跑 **2** 遍

**上一轮(v0)是我给的基线,不是 LLM 的上限。** 一次直判是最容易被打败的做法,
用它的成绩宣布「本体更好」不成立。这一轮把 prompt 认真做三档,
看差距到底来自 prompt,还是来自结构。

| 档位 | 做法 |
|---|---|
| v0 | 一次性直判(上一轮的基线) |
| v1 | 判据细化 + 先证据后结论(仍未拆步) |
| v2 | 先抽证据,再基于证据判(两遍,最接近本体) |
| v3 | v2 + 逐条自我复核(三遍) |

## 二、要害一:v0 那股「不敢判」追回来没有

v0 最大的毛病不是判错,是**不敢下结论** —— 48 格退成未知,而本体在这些格子上有判定。
如果加了明确判定标准之后未知数掉下来,说明那是 prompt 问题,不是 LLM 的上限。

- **v0**:未知 **48** 格(本体侧 9 格)
- **v1**:未知 **5** 格(本体侧 9 格)
- **v2**:未知 **6** 格(本体侧 9 格)
- **v3**:未知 **7** 格(本体侧 9 格)

## 三、要害二:LLM 看得见本体看不见的,升级后还看得见吗

上一轮人工点开原文核过 **13 格**方向相反的分歧,结论是 **LLM 对、本体错** ——
本体词表漏了「线材线束」「邀请客人验厂」「不良制程改善」这些同义表达。

如果升级 prompt 之后这些格子**仍然和本体不一致**,说明 LLM 的正确性没被牺牲:
那差距就只剩「可复算」这一件事,而那不是准确率问题。

## 六、结论

- **「未知」从 48 降到 7(少 41 格)**。说明 v0 那股「不敢判」的劲儿主要是 prompt 造成的,**不是 LLM 的上限** —— 我上一轮把这一点归错了。
- 人工核对的那 13 格(LLM 对 / 本体错)在 v3 里保住 **13/13** —— 升级 prompt **没有**把它的「看得见」牺牲掉。
- 自一致性:v3 为 97%;代价 60 次调用 / 144s(本体侧是毫秒级纯计算)。
- 余下 19 格里,人工判定 **v3 对 11 格**、**v3 错 3 格**、材料不对称 4 格、待定 1 格。
- 加上上一轮核过的 13 格,**本体在这批人上至少错了 24 格**;v3 自己错 3 格。**在这个样本上,认真写 prompt 的 LLM 准确率高于本体。**

**所以答案是分层的:**

1. **准确率这一层,你问得对:prompt 能追平,而且能超过。** 说「LLM 判不了」是不对的 —— 判据讲清楚、先证据后结论,它把「不敢判」变成了「敢判」,还捡回了本体词表漏掉的同义表达。
2. **来源这一层,prompt 追不平。** v3 有 4 格判「未知」是因为**我把年龄只喂了一份材料**;本体知道那个年龄来自平台/HR 派生量而不是简历。**LLM 只看得见你递给它的东西** —— 而"该递什么、每条来自哪里",正是本体那一层在做的事。
3. **自校验这一层,prompt 反而更危险。** v3 出现过一次「理由写应判不满足、标签却写满足」,自洽到只有人点开原文才发现。三步流程比一步流程更容易产生这种"看起来有依据"的错。
4. **可复算这一层,prompt 追不平。** 自一致性不满 100% 的东西再准也当不了门禁;本体侧同输入必同结论,这是结构给的。
5. **可审计这一层,差别不在方法。** v2/v3 那种「先抽后判 + 复核」其实已经是**用散文写成的本体** —— 结构在,只是写在提示词里而不是文件里。把它当本体用,就要接受它的结构不可 diff、不可被门禁复查。

> 一句话:prompt 能追平**准不准**,追不平**凭什么**。产出只需要「看」,LLM+好 prompt 就够;产出需要「半年后能查出凭什么」,结构必须落在文件里 —— 而那时你会发现,v2/v3 已经在做本体的事了。
