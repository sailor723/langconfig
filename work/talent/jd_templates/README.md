# JD 模板:一份骨架 + 两版裁剪

```
_common.yaml    S1 岗位标识(含 S1.11 岗位类别)/ S7 元数据 / S8 合规声明    24 字段
manager.yaml    经理岗:S2 目标与 KPI、S4 职责与授权、S5/S6 降级           23 字段
staff.yaml      员工岗:S4 少量、S5 作业明细为主、S6 作业条件             18 字段
```

两版都 `inherits: _common.yaml`。**共用部分必须只有一份** —— 抄成两份必然分叉,
`render_jd_final`(42 条)与 `jd_input_form`(29 条)之间那 13 个空指引就是这么来的。

## 用哪一版:由 `S1.11 岗位类别` 决定,不由岗位名决定

实测反例:**「品质经理」名字带"经理",但原文写「直接下属:无」** —— 按名字套经理岗模板,
会去问"管理幅度多少人、预算多少"(空问),同时把"作业频次/时长"这些真正该问的降级掉。

```
直接下属 = 有具体人员  → manager.yaml
直接下属 = 无          → staff.yaml
直接下属 未写          → 判不了 → 标 A 级空白「待确认岗位类别」,先问业务方
```

10 份 JD 里的现状:**业务跟单、关务报关员** 原文未写直接下属 → 判不出来(不许猜);
**品质经理** 走员工岗模板。

## owner 只有两个值

`business` / `hr`。**客户就是业务方**(这里的"客户"是客户公司的业务团队),
所以 `client` 这个值作废 —— "客户答授权"和"业务方答管多少"是同一个人在答。

## 每个字段六列

| 列 | 含义 |
|---|---|
| `level` | A 阻断(不填招不了人)/ B 解释(能算但说不清为什么)/ C 归档(只影响完整性) |
| `owner` | `business` 或 `hr` —— 谁才答得出来 |
| `why` | 不填这一项,下游会怎样。要具体,不写"提高完整性" |
| `how` | 可直接照抄的填法(枚举类把选项列全) |
| `shape` | `text`/`number`/`enum`/`date`/`list`/`bool`,给门禁校验值用 |
| `not_applicable` | (只在两版文件里)这一版明确不填的码,并写明为什么 |
