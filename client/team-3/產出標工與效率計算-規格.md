# 產出標工與效率計算工具 — 規格

- 版本：v1 草案（2026-11-13）
- 適用：HY 廠、DG 廠，2026 年 10 月為驗收基準月
- 狀態：待確認

---

## 問題陳述

每月月底，PIE 要交出「各生產部門產出標工 + 效率」這份數據。現在的做法是：

1. 把 SAP 的生產報數導出，逐部門貼進該部門的「產出標工計算表」；
2. 靠表內 VLOOKUP 去 `標準工時數據庫` 抓標工，再乘報數、除以 3600、按新舊款決定是否乘 0.85；
3. 再從全廠工時明細裡，按「固定 / 做辦 / 非W轉W級 / 納入效率計算」等人工分類，挑出「考核效率的總出勤工時」；
4. 最後 `實際效率 = 產出標工工時 ÷ 考核出勤工時`，跟部門效率目標比。

痛點：

- **20+ 份模板，公式口徑各寫各的**。同一件事（例如 0.85 係數、前後段產量怎麼認定）在不同文件裡寫法不同，規則只存在於 Excel 公式與老員工記憶裡。
- **工時側全靠人工分類**，人員分類一改就要重挑一次，且無法回溯「為什麼這 100 小時被排除」。
- **結果不可復現**。同一份數據隔月重算，數字會漂。
- **查不到標工的款號被靜默算成 0**，效率虛高，部門拿這個來申訴。
- 兩廠模板不同，每廠每月都要重來一遍。

## 解決方案

做一個**本機命令列工具**（Python），每月執行一次：

```
輸入：①各部門「產出標工計算表」（產量明細 + 標準工時數據庫）
      ②全廠工時明細
      ③部門效率目標（配置）
輸出：①部門效率匯總表  ②各部門產出標工明細  ③異常清單
```

規則（哪些行算產量、標工查哪一欄、要不要乘 0.85、哪些人的工時計入考核）全部外置成**配置文件**，改口徑不改代碼。

10 月作為驗收基準：工具算出的每部門產出標工與效率，必須與現有手工表對得上，否則不算完成。

## 用戶故事

1. 作為 PIE，我想要一條命令跑完兩廠所有部門，以便月底不用逐份開 Excel。
2. 作為 PIE，我想要輸出同時給出「產出標工工時、效率目標、考核出勤工時、實際效率、差距、是否達標」，以便直接貼進 KPI 表。
3. 作為 PIE，我想要每個部門的明細保留每筆報數的計算過程（款號、標工、報數、係數、工時），以便部門申訴時能逐筆對質。
4. 作為 PIE，我想要一份異常清單，列出「查不到標工的款號 / 標工為 0 / 報數為 0」的記錄，以便送 IE 補標工，而不是讓它靜默變 0。
5. 作為 PIE，我想要口徑差異（例如 DG 的 0.85 只對舊款生效）寫在配置裡，以便明年換人也不會算錯。
6. 作為部門主管，我想要看到自己部門每張生產單、每個款號貢獻了多少標工工時，以便判斷是產量不足還是效率不足。
7. 作為 PIE，我想要工具對同一個月重複執行結果完全一致（冪等），以便財務復核。
8. 作為 PIE，我想要工時側的排除明細可查（哪個工號、什麼分類、為什麼不計入），以便回應「我的工時被吞了」的質疑。
9. 作為 IE，我想要工具在標工庫缺少某款號時列出來，以便維護 `標準工時數據庫`。
10. 作為 PIE，我想要兩廠共用同一套引擎、只換配置，以便新增部門時不必寫新代碼。

## 實現決策

### 分層

| 層 | 職責 |
|---|---|
| 源讀取層 | 統一檔案格式（.xls/.xlsx/.ods → 記憶體表格）；不改變原檔 |
| 模板適配層 | 每部門一份 adapter，聲明：表名、欄位名、行篩選條件、標工查找鍵、取哪一欄、係數規則、匯總口徑 |
| 標工引擎 | 逐行算 `產出標工工時`，累加到部門 |
| 工時規則引擎 | 按人員分類規則，從工時明細匯出 `考核效率總出勤工時` |
| 報表層 | 匯總表 / 明細 / 異常清單，三個 sheet 一個工作簿 |
| 配置層 | `config/` 下 YAML：部門清單、模板參數、工時分類規則、效率目標 |
| 校驗層 | 與 10 月手工表逐部門比對，輸出誤差報告 |

### 已確認的口徑（來自現有公式，逐條複刻）

**A. DG 前後段型模板（金架九部/燒焊/磨光/成品部）**

```
新舊款 H  = IF(OR(LEFT(款號,2)="M3", LEFT(款號,3)="T14", LEFT(款號,4)="H128",
                  LEFT(款號,4)="H129", LEFT(款號,3)="T15"), "新款",
              IF(物料主檔命中(款號) = 未命中, "舊款", "新款"))
前段標工 A = VLOOKUP(LEFT(成品款號,6), 標準工時數據庫!A:E, 5)   # 前段總工時
後段標工 C = VLOOKUP(LEFT(成品款號,6), 標準工時數據庫!F:T, 15)  # 後段總工時
前段總工時 B = IF(新款, A×前段報數/3600, A×前段報數/3600×0.85)
後段總工時 D = IF(新款, C×後段報數/3600, C×後段報數/3600×0.85)
前段報數 F = IF(工作中心描述="SH分公司前工序" 且 種類a="架", 生產報數, 0)
後段報數 G = IF(工作中心描述∈{"SH分公司包裝","SH分公司包裝HY"} 且 種類a="架", 生產報數, 0)
部門產出標工 = SUMIF(月份=YYYYMM, B) + SUMIF(月份=YYYYMM, D)
```

> **0.85 只在「舊款」分支生效**，這是 DG 的既有口徑，必須保留。

> **口徑變更（2026-11-13 確認）**：數量與行篩選一律取 `生產報數`，不再取 `生產報數PR`。
> 已用金架九部 10 月 523 行實測：兩者在「架」類行數值完全相同（前段合計 2317.6480、後段 3454.0311、合計 5771.6790，與手工表分毫不差）；差異僅出現在「配件」類行（PR = 生產報數 ÷ 2，例：生產報數 430 / PR 215），而配件行本就不計入架類，故對結果無影響。

**B. 產量口徑（兩廠共通）**

- 只統計 `生產報數` 有數值、且 `時效 ≠ "不計"` 的行為準；
- 返工數量、報廢數量不另計（不從報數中扣減，也不重複計）；
- 配件類訂單（`種類a = "配件"`）不計入架類前後段工時，另走配件工時表；
- 外協、幫工、辦單若已在產量明細的報數行中，照行計入；未在表中的人工補錄不做。

**C. 效率口徑（與 KPI 表一致）**

```
當月完成品標準工時 i = 部門產出標工工時（小時）
考核效率總出勤工時 m = Σ 工時明細中「計入考核」人員工時（含加班）
                        + 調入工時 − 調出工時 ± 調整工時 − 申訴扣減工時 + 被申訴工時
效率目標 j = 配置中的部門目標（如 CNC中心 0.81、膠架二/三/五部 0.76、配件三部 0.87）
實際效率 n = i / m
當月目標定額工時 l = i / j
差距 p = n - j
是否達標 = n ≥ j
```

**D. 工時側分類規則（寫進配置，可逐條追溯）**

以工時明細的 `部門屬性` 為考核部門歸屬，按以下順序判定：

| 判定 | 條件 | 計入考核 |
|---|---|---|
| 排除 | 人員分類含 `-固定人員`（管理/固定崗） | 否 |
| 排除 | 人員分類含 `-辦單` 或 KPI屬性 = `做辦` | 否（另計辦單工時） |
| 排除 | KPI屬性 = `浮動` | **否** |
| 納入 | 人員分類含 `-納入效率計算` | 是 |
| 納入 | KPI屬性 = `非W轉W級` | 是 |
| 納入 | 在職情況 = `離職` | **是**（按當月實際工時計） |
| 納入 | 其餘（KPI屬性 = `其他`，且不屬於上述任何一條） | 是 |

**D2. 調入 / 調出（幫工工時）**

DG 廠的調入調出**不從 `26年10月工時-XY.xls` 取**，而是從 KPI 工作簿 `01每月生產各部KPI達成表現財務初步數據計算2026.10.xls` 的 **`幫工工時`** 工作表：

```
左側（原部門/組/班 + KPI屬性 → W級 / 非W級 / 總計） → 該部門「調出工時」
右側（借調部門/組/班 → W級 / 非W級 / 總計）        → 該部門「調入工時」
```

- **調出**：只計「參與效率考核」的借出工時——即 KPI屬性 ∈ {`其他`, `非W轉W級`}；`做辦`、`浮動`、`固定` 的借出工時**不計入調出**（他們本就不在考核分母裡）。
- **調入**：**全部計入**，W 級與非W級都算（依 KPI 表原註記「帮工调出人员只填参与效率考核人员工时，调入的则都要算上工时」）。
- 逐筆依據在 `幫工明細` 工作表：工號、姓名、原部門、借調部門、借出/入、小計、級別1、KPI屬性。明細輸出要保留這些欄位。

**HY 廠**：本月 `2610全廠工時-XJ.xls` 內**沒有** `幫工工時` 工作表（該檔僅 rep-kpi / rep-人均時產 / 工時明細 / 屬性 / 工作日制 五張），故 HY 的調入/調出**沿用 KPI 表手填值**，由月度配置檔讀入。

**E. 取數邊界（v1）**

工具讀取**每部門「產出標工計算表」內既有的 `產量明細` 與 `標準工時數據庫` sheet**，用 Python 重算標工欄位與匯總——即「替代 Excel 公式」，不含人工粘貼環節。

理由：產量明細含大量人工補錄列（外協、幫工、辦單、PR 標記），直接吃原始 SAP 導出等於把這些判斷也重寫一遍，風險大且無法驗收。等 v1 與手工表完全對齊後，再把「粘貼」這一步自動化（v2）。

### 輸出契約

`outputs/YYYYMM_效率匯總.xlsx`，三個 sheet：

- `匯總`：廠別 | 部門 | 合格報數(架) | 產出標工工時(h) | 效率目標 | 目標定額工時(h) | 考核出勤工時(h) | 實際效率 | 差距 | 是否達標 | 異常筆數 | 口徑提示
- `明細`：廠別 | 部門 | 生產單號 | 成品款號 | 標工鍵 | 新舊款 | 前段標工 | 前段報數 | 前段工時 | 後段標工 | 後段報數 | 後段工時 | 合計工時 | 來源(檔案/sheet/行號)
- `異常`：類型(查無標工/標工為0/報數為0) | 廠別 | 部門 | 生產單號 | 成品款號 | 報數 | 來源定位

### 技術決策

- 語言：Python 3（本機 runtime 已有 pandas/openpyxl/xlsxwriter）
- 舊版 `.xls` 轉換：優先用本機 OpenOffice headless 轉 xlsx（`soffice --headless --convert-to xlsx`），轉換失敗則報錯並要求提供 xlsx；**不做 BIFF 解析**
- 配置：YAML（部門、模板、目標、工時規則），不含業務代碼
- 不用 Excel 公式做最終計算：所有數字在 Python 內算完再寫出，避免「打開才重算」

## 測試決策

**只驗證外部行為：給定輸入檔案，輸出的數字對不對。不測內部函數實作、不測 Excel 樣式。**

1. **黃金基準回歸（主要防線）**：10 月每部門一份測試——工具輸出的部門產出標工工時 vs 該部門手工表 `月產出標工匯總表` 數值，相對誤差 ≤ 0.5%。
2. **效率端對齊**：輸出的 `實際效率` vs `01每月生產各部KPI達成表現財務初步數據計算202610.xls` 的 `實際效率` 欄，相對誤差 ≤ 0.5%。
3. **口徑單元測試**（用小型合成數據，不碰真實檔）：
   - 新款不乘 0.85、舊款乘 0.85；
   - 前綴 M3/T14/H128/H129/T15 強制判定為新款；
   - 配件行（種類a=配件）不計入前後段；
   - 時效="不計" 的行不計；
   - 查無標工 → 0 且進異常清單；
   - **數量一律取 `生產報數`**：若某行 `生產報數 ≠ 生產報數PR` 且該行計入架類，須在匯總表「口徑提示」中列出（用於發現模板間不一致）。
4. **工時規則測試**：固定人員/辦單人員/浮動人員被排除；納入效率計算、非W轉W級、離職人員被計入；調入調出加減正確。
   - 回歸錨點：HY 廠 10 月按規則加總須等於 973.67（配件部/鐳射組）、10794.47（脾形中心）、21529.57（膠架五部），誤差 0。
   - 調整後對齊：加上調入/調出/調整工時後，上述各部門須等於 KPI 表 `考核效率的總出勤工時`，誤差 ≤ 0.5%。
5. **幫工工時測試**（DG）：
   - 從 `幫工工時` 左表重算的調出，金架燒焊部 468.5、金架磨光部 104.5、脾形部 361.5、注塑噴塗部 180.5、加色部 1698.98，須與 KPI 一致；
   - 從右表重算的調入，配件一部 546、金架成品部 748、金架燒焊部 346、金架磨光部 405、脾形部 67.5、注塑成品部 782.72，須與 KPI 一致；
   - 浮動/做辦/固定 的借出工時不得進入調出（用 `注塑成品部` 的 27h 浮動借出當反例）。
6. **冪等測試**：同一輸入連跑兩次，輸出完全一致。

驗收門檻：批次內每部門都要通過 1 與 2。任何一部門不過，先解釋差異，不調容差。

## 進一步說明

- **最大風險是模板異質性**：`加色一部` 的標工庫有 12232 行 × 256 欄、鍵是「款號+工序組合」、還有 `加腳` 減半與多餘鐳射絲印標工扣減。批次 4 可能不是「配置」能解決的，屆時會退化成一個專用 adapter（仍是配置 + 少量代碼），這點先講明。
- **0.85 的來源未查明**：目前只確認「舊款乘 0.85、新款不乘」這個行為。工具會照抄行為，但不解釋其業務含義；若日後口徑要改成「全部乘」或「全部不乘」，只需改配置一行。
- **工時側的「納入效率計算」是人工打標**，本質上是管理判斷，工具只能複刻，不能自動推斷。若某月標記缺失，工具會把該部門的排除規則列出，讓 PIE 確認。
- **檔案命名**：11 月起沿用 `XX部產出標工計算表{月}.xls` / `XX部2026產出標工計算表{月}.xls` 這套規則（已確認）。配置以「廠 + 部門 + 檔名模式」定位檔案，月別只改一個參數。
- **調整項目前是人工填在 KPI 表裡的**（調入/調出/調整/申訴）。v1 的處理：工具算出「按規則加總」的值，調整項從配置檔（每月一份，PIE 填）讀入，兩者在明細裡分列，避免調整被埋在公式裡看不見。
