## 问题陈述

集团四个厂区（HQ 总厂、SW、OS、NB 越南）的会议数据分散在两个系统里：平台 A 负责录音转写生成纪要全文，平台 B 负责登记会议与决议事项。两套数据之间没有关联，结果是：

1. **会议投入不可见。** 全年 2200 场会、3562 项决议、约 21938 人时，没有任何一处能回答「会议花了多少成本、花在哪个维度上」。
2. **闭环数据不可信。** 完成率 98.7%，但 1349 条有完整时间的事项里有 1288 条「实际完成时间」等于计划时间（95.5%），超期率仅 3.7%。这是自报完成，不是真闭环。
3. **责任落不下去。** 45.9%（1634/3562）的决议事项没有责任人，只能归到主导人部门。
4. **会议结构没人量化。** 「计划会议」一个会名一年开 763 场，占全部会议的 35%；14:00 开 1141 场；18:00 后还有 277 场。
5. **重复议题识别不出来。** 纪要中位数只有 4 个字，45.4% 干脆就是「无」。现有系统只能比对会议名称相似度，识别的是「重复开会」，不是「重复议题」。
6. **现有平台无法多人使用。** 单文件 HTML，数据存在各人浏览器 localStorage，权限判断写在前端 JS 里——改一行代码就能看到全集团数据。厂长和董事长看到的可能不是同一份数。

对管理者而言，真正的问题不是「开了多少会」，而是：**这场会解决了几件事、有没有真闭环、下个月还会不会为同一个问题再开一次。**

---

## 解决方案

把平台 B 从单文件原型重写为服务端多人系统，并把数据模型从两层扩到三层：

```
会议 (1) → 议题 (N) → 决议事项 (M)
```

- **会议层**：厂区、日期、类型、时长、主导人、参会人、场所、纪要全文
- **议题层**（新增）：议题标题、讨论摘要、决议、问题指纹
- **决议层**：事项内容、责任人、责任部门、期限、佐证四件套、AI 审核、上级审核、结案状态

围绕这层结构提供：

- **四级权限**（集团总负责人 / 分厂厂长 / 部门负责人 / 当事人），服务端行级鉴权，越权返回空集而非 403 报错页
- **闭环门槛**：佐证四件套 + AI 审核 + 上级审核，四者齐备才能结案
- **十个分析维度**：SQCDS（安全/质量/成本/交期/服务）+ 4M1E（人/机/料/法/环）
- **问题指纹**：`对象类型:对象编号:问题类型`，让同一问题第 N 次上会被识别出来
- **人时与成本**：参会人数 × 时长，可配置人均小时成本换算
- **预警**：红（超期）/ 黄（临期），连续超期升级上级，夜间与周末静默

保留原型全部功能模块（集团总览、分厂、维度、会议明细、我的任务、统计分析、成绩统计、会议知识库、平台配置、功能导览），但按垂直切片分批交付。

## 实现决策

### 将构建的模块

| 模块 | 职责 |
|---|---|
| `auth` | 账号密码登录、会话、用户与角色、外部 ID 预留 |
| `org` | 组织架构（厂区/部门/人员/别名规则），HR 接口可选接入 |
| `ingest` | 平台 A 接口同步 + 文件导入，字段别名映射，表头识别，行级校验与警告 |
| `normalize` | 会议类型归一化、参会人拆分、时长清洗、部门归口、问题指纹生成 |
| `meeting` | 会议、议题、决议三层实体与状态机 |
| `closure` | 佐证四件套、AI 审核（规则引擎）、上级审核、结案 |
| `metrics` | 聚合计算：人时、闭环天数、SQCDS/4M1E、重复议题、效能指数 |
| `scope` | 行级权限：厂区 → 部门 → 本人 |
| `views` | 集团总览、分厂、维度、会议明细、我的任务、统计分析、成绩统计、知识库、配置、导览 |
| `alert` | 红黄预警、连续超期升级、夜间周末静默、订阅 |
| `export` | 报表导出（Excel） |

### 模块接口（REST，`/api/v1`）

```
POST /auth/login                    账号密码登录，返回 JWT
GET  /me                            当前用户、角色、数据范围

POST /ingest/sync                   触发接口同步（幂等，生成快照）
POST /ingest/upload                 上传 CSV/XLSX
GET  /ingest/last                   上次导入的映射结果、警告行、计数

GET  /meetings                      列表，支持 code/date_range/type/dept/dimension/keyword
GET  /meetings/{id}                 会议详情（含议题与决议）
GET  /meetings/{id}/minutes         纪要全文（含来源标记 asr/manual/none）
POST /meetings/{id}/topics          手工补录议题（纪要缺失时）

GET  /tasks                         我的任务 / 部门任务，按状态排序
POST /tasks/{id}/evidence           上传佐证（四类之一）
POST /tasks/{id}/ai-review          触发 AI 审核
POST /tasks/{id}/submit             提交上级审核
POST /tasks/{id}/approve            上级审核通过 / 驳回
POST /tasks/{id}/close              结案（前置校验）

GET  /metrics/overview              集团总览 KPI
GET  /metrics/factory/{code}        分厂指标
GET  /metrics/dimension             按 SQCDS / 4M1E 聚合
GET  /metrics/trend                 期间对比（本月/本季/本年/近 12 个月）
GET  /metrics/repeat                重复议题（问题指纹聚合）

GET  /kb/search                     知识库检索
GET  /alerts                        预警列表
GET  /admin/config                  阈值、类型归一化表、别名规则
PUT  /admin/config
GET  /admin/audit                   审计日志
GET  /export/report                 报表导出
```

### 技术与架构决策

1. **技术栈**：Python 3.12 + FastAPI + SQLAlchemy + PostgreSQL 16；前端 React 18 + TypeScript + Vite。
2. **所有聚合在服务端计算**。前端不持有全量数据，不做权限判断——这是与原型最根本的差别。
3. **权限是行级查询条件，不是页面开关**。每个仓储层方法强制接收 `Scope`（厂区集合 / 部门 / 本人），越权返回空集。
4. **数据接入是「快照」模型**：每次同步生成一个不可变快照，写入 `ingest_run`，事务内切换当前版本。失败保留上一份，不污染线上数据。
5. **会议编号**：`{厂区}{YY}{MM}{3 位月内流水}`（如 `HQ2605001`）；重复次数独立字段 `repeat_no`，由「同厂区 + 同主导人 + 会议名称相似度 ≥70%」累计。
6. **问题指纹**：`{对象类型}:{对象编号}:{问题类型}`，由规则从议题/事项文本抽取；抽不出时不猜，标记 `unresolved` 并进入人工确认队列。
7. **AI 审核是规则引擎，不是大模型**。评分沿用「人 40 + 事 60（正确/逻辑/重复各 20）」，阈值可配置，结论必须落库并可复算。
8. **纪要全文可插拔**：`minutes_full` 为空时，议题层降级为「一议题一事项」，重复识别退化为会议级；接入后按会议编号回填，不阻断其他功能。
9. **归档**：明细在线 12 个月，更早数据按月聚合成 `archive_monthly` 表，保留原始快照可回查。
10. **时区**：全系统 `Asia/Shanghai`，接口返回 ISO 8601 带时区偏移。

### 数据与 API 约定

- 三层实体与字段沿用 01 文档的字段契约，不在此重复。
- 枚举值统一大写英文（`SHORTAGE` / `MATERIAL_DEFECT` / …），展示层映射中文。
- 所有列表接口统一分页：`?page=1&size=50`，返回 `{items, total, page, size}`。
- 错误响应统一 `{code, message, detail}`，业务码与 HTTP 状态分离（如 403 也可能是「数据范围为空」）。
- 写入接口一律幂等键（`Idempotency-Key`），防止表单重复提交。
- 时间字段一律 `timestamptz`，禁止存本地时间字符串。

## 测试决策

**只验证外部行为**：HTTP 接口契约 + 页面可观察行为。不测私有函数、不测实现细节。

将测试的模块：

1. **权限边界**（最高优先级）
   - 厂长为 A 厂时请求 B 厂数据 → 返回空集，不是 403 报错页
   - 部门负责人请求本厂其他部门 → 空集
   - 当事人请求他人任务 → 空集
   - 管理员接口对非管理员 → 403
2. **闭环门槛**
   - 缺任一件佐证 → 结案被拒，返回缺失项
   - AI 审核未通过 → 上级审核被拒
   - 上级未通过 → 结案被拒
   - 四个条件齐备 → 结案成功，状态、时间、操作人正确落库
3. **口径一致性**
   - 同一批数据在「集团总览 / 分厂 / 维度 / 会议明细」四处出现的人数、场次、事项数必须一致
   - 会议类型归一化后，「非会议」（面试、接待客户）不计入会议统计
   - 时长缺失时按 时段 推算，仍缺失则按默认值并标记
4. **重复识别**
   - 同一问题指纹第二次出现 → `repeat_count=2`
   - 不同对象、不同问题类型 → 不合并
   - 指纹抽取失败 → 进人工确认队列，不静默丢弃
5. **导入幂等与降级**
   - 同一文件导入两次 → 数据量不翻倍
   - 接口失败 → 沿用上一快照，页面顶部提示
   - 表头别名变化（会议主题 / 会议名称 / 主题）→ 仍能识别
6. **归档**
   - 13 个月前的明细查不到，但月度汇总可查

**测试风格**：项目目前没有测试基线，从零建立——后端 `pytest` + `httpx.AsyncClient` + 事务回滚夹具；前端 Playwright 只覆盖三条主链路（登录看板、上传佐证、结案）。数据夹具用 3562 行真实数据脱敏后的子集（约 300 行，覆盖四厂、重复议题、无责任人、缺佐证等边界）。

## 范围外

- **实时语音转写与说话人分离**——平台 A 的职责，本系统只消费其结果
- **个人发言分析**（谁说了多少、谁不发言）——数据源不支持，且不属本次目标
- **绩效奖金计算、与人事/薪酬系统对接**——本系统只到「改进建议」，不做奖惩落地
- **移动端 App**——第一版只做响应式 Web
- **第三方推送渠道**（企业微信/钉钉机器人）——第一版只做站内消息 + 邮件摘要
- **数据大屏/会议室投屏**——不做
- **跨集团多租户**——单集团四厂，不做租户隔离
- **旧 HTML 原型的运行时迁移**——原型只作规格参考，不保留其 localStorage 数据
- **OCR / 图片纪要识别**——不做
- **会议成本财务核算**——人时可算，金额只做展示系数换算，不做财务凭证
