Enterprise Study Narrative

From mock business data to a skill-guided SQL analysis experience

This page explains how the Sun Hing study is structured inside LangConfig. The real source of truth is the SQLite database, the business meaning lives in SKILL.md, the dashboard HTML pages are the presentation layer, and the chat agent combines skill guidance with SQL execution to answer user questions.

The current implementation is already metadata-driven at the dashboard selection layer, but dashboard layout generation is still mostly Python-driven rather than fully derived from SKILL.md.

1. End-to-End Process

This is the refined version of the study flow based on the current code and agent behavior.
1

Data Cleaning And Input

The Sun Hing case currently uses mock business data, then loads it into a structured SQLite analysis DB.

  • Raw source tables preserve operational detail
  • Dimension + fact tables support KPI and ROE analysis
  • ERD is the visual explanation layer for this schema
2

Companion Skill

SKILL.md is the semantic companion to the DB. It does not store the facts, but explains how to interpret them.

  • Business context
  • KPI / factor grouping
  • Preferred query path
  • When to use fact tables vs raw tables
3

HTML Generation

The current Sun Hing dashboards are generated mainly from Python logic over SQLite, while carrying skill metadata in the HTML head.

  • Current state: Python-first layout generation
  • Metadata in HTML links DB + skill + entry mode
  • Target state: stronger SKILL.md-driven generation
4

Hub And Detail Pages

The suite includes one main hub page and multiple factor/detail pages for drill-down analysis.

  • Main hub = executive cockpit
  • Detail pages = factor dashboards
  • ERD and Gantt pages = explanation pages
5

LangConfig UI

The Analysis UI uses the selected dashboard HTML as the context anchor for everything else.

  • Shows hub HTML in the iframe
  • Loads embedded data for Data panel
  • Loads linked skill files for Skill panel
  • Uses dashboard metadata to configure chat
6

Analysis Chat

Chat is skill-guided, but it still depends on backend system rules and SQL/Python tools to produce answers.

  • Reads dashboard-linked skill metadata
  • Loads SKILL.md content
  • Runs SQL on SQLite for verification
  • Answers in business terms, not raw schema terms

3. Role Of Each Artifact

The biggest confusion usually comes from mixing up source-of-truth, semantic layer, and presentation layer.

Database / Schema

The SQLite DB is the factual base. It stores the actual records and the consolidated KPI / ROE fact tables used for analysis.

Meaning: data truth layer.

ERD HTML

The ERD page is an illustration layer. It explains how raw tables, dimensions, and fact tables relate to one another.

Meaning: schema explanation layer.

SKILL.md

The skill file is the business-meaning companion. It translates table structure into executive concepts like ROE factors, KPI families, and recommended query order.

Meaning: semantic interpretation layer.

Dashboard HTML

The dashboards are what users see first. They are presentation pages, not the final authority for numerical truth.

Meaning: visualization and navigation layer.

Analysis UI

The LangConfig Analysis page uses the selected HTML as the anchor to open the dashboard, skill panel, data panel, and chat panel together.

Meaning: user operating surface.

Analysis Chat

The agent reads the dashboard-linked skill, then executes SQL on SQLite to answer questions in business language. It should verify values rather than trust rendered HTML numbers.

Meaning: skill-guided SQL reasoning layer.

4. User Journey In LangConfig

This is what the user experience looks like from opening the study to asking a question.

A. Open Main Hub

The user opens the Sun Hing main dashboard. This acts as the entry page for the whole study.

Why it matters: hub HTML is easier to govern than exposing every detail page directly.

B. Explore Detail Pages

From the hub, the user can drill down into Profit, Turnover, Leverage, Support, Risk, ERD, and Gantt pages.

Why it matters: each page narrows the management lens without changing the study context.

C. Read Data And Skill

The UI can load embedded dashboard data plus the skill content associated with the selected HTML page.

Why it matters: the user sees not only the picture, but also the source rows and business explanation.

D. Ask Analysis Questions

The user asks a natural-language question in Analysis Chat, such as asking about an ROE factor or KPI.

Why it matters: the question is interpreted with the study's business semantics rather than a generic SQL mindset.

E. Agent Resolves Context

The backend reads dashboard metadata, loads the linked skill, resolves the DB path, and starts the deep agent with SQL tools.

Why it matters: the selected HTML decides the correct study context automatically.

F. SQL Verification And Answer

The agent runs SQL on SQLite, interprets the result with SKILL.md, and returns a business-facing answer.

Why it matters: answer source is database truth, not just what the card visually displays.

5. Current State Vs Target State

This table captures the exact architecture point you highlighted during the review.
Topic Current State Target Direction
Data Truth SQLite DB is the source of truth. Keep DB-first; never shift truth to static HTML.
Business Semantics SKILL.md defines the business interpretation layer. Keep strengthening the semantic contract, not SQL hardcoding.
Dashboard Generation Mostly Python-driven layout and calculation logic. Move toward stronger SKILL.md-driven dashboard structure.
Dashboard Selection Already metadata-driven using HTML meta block. Keep this pattern for future business studies.
Analysis Chat Skill-guided plus backend prompt plus SQL/Python tools. Keep direct answers while preserving SQL verification.
Key design principle: DB stores the facts, SKILL.md stores the business meaning, HTML stores the presentation and navigation, and Analysis Chat combines all three to deliver a usable enterprise-study experience.

6. Recommended Reading Path

If a new user wants to understand the full study quickly, this is the best route.

Path 1: Executive View

Open the main dashboard first, then drill down into factor pages based on the management question.

Path 2: Data Understanding

Read the ERD page to understand raw tables, dimensions, fact tables, and lineage before validating metrics.

Path 3: Business Meaning

Read the linked SKILL.md to understand what each factor means and how the agent should interpret natural-language questions.

Path 4: Agent Validation

Use Analysis Chat to ask direct questions and force SQL verification when checking dashboard numbers.
