# 产品需求文档 Product Requirements Document (PRD)

## 2. 背景与问题

- **目标使用者**：生产计划员、采购员、订单管理员、生产部门负责人
- **使用者目前的工作流程**：人工跟进物料、排产、生产部门沟通处理异常
- **现在最大的痛点**：物料导致停工、订单违约、部门相互推诿
- **这些痛点造成的成本**：误工损失、沟通内耗
- **为什么需要 AI Agent**：自动抓取真实数据 、快速决策、消除协同壁垒
- **为什么现在是做这件事的好时机**：人工模式效率低，急需AI实现全流程闭环管控 

## 3. 产品目标

- **主要目标**：打通物料、生产和订单数据自动预警、决策和执行
- **次要目标**：沉淀管控标准，降低沟通成本，提升协同效率
- **不做的范围**：不替代对外人工对接，不处理非物料类生产异常
- **成功定义**：违约率、停工时长、推诿工单显著下降
- **预期带来的业务价值**：减少损失，提升客户满意度，完善风险管控体系
## 4. 使用者与场景

- **核心使用者角色**：生产计划员、订单管理员、管理层
- **典型使用场景**：物料预警、排产调整、交付风险评估
- **高频场景**：日常物料到货预警、生产排程自动调整、订单交付风险自动评估
- **低频但高风险场景**：核心订单断供，需高层介入决策
- **例外场景**：供应商破产、政策突变等极端供应链问题
- **不适用场景**：设备故障、产品质量引发的交付异常

## 5. Agent 定位

- **Agent 角色**：助理 / 教练 / 审核员 / 执行者 / 协调者：业务协调者、规则执行者、风险审核员
- **Agent 要帮使用者完成什么任务**：抓取全链路数据、三维标准评估、推送工单与预警、上报决策层
- **Agent 的语气与风格**：客观严谨，以数据为依据，仅输出事实与执行建议
- **Agent 的自治程度**：常规动作自动执行，重要决策需人工确认
- **需要人工确认的节点**：核心客户订单、大额赔付方案调整
## 6. 核心流程

1. **使用者如何启动任务**：系统自动预警 / 人员手动发起
2. **Agent 如何理解需求**：匹配订单、物料、交付周期等关键数据
3. **Agent 如何搜集资料或呼叫工具**：对接ERP、采购、生产、客户管理系统
4. **Agent 如何做判断或生成结果**：依据效能、效率、杠杆三维标准评估方案
5. **Agent 如何回传结果给使用者**：输出风险报告与决策建议
6. **使用者如何确认、修改或重做**：采纳、修改方案或转高层处理
7. **任务完成后如何记录或追踪**：自动留存日志，沉淀风险案例
## 7. 功能需求

- **必备功能 1**：全链路数据关联、履约风险评估、协同工单生成
- **必备功能 2**：订单履约风险自动评估（基于三维核心标准）
- **必备功能 3**：跨部门协同工单自动生成与推送
- **必备功能 4**：支持日报、周报、月报与专题分析模式
- **进阶功能**：供应商逾期预警、客户风险通知自动生成
- **未来版本功能**：供应链风险预测、履约数据可视化看板
## 8. 能力边界

- **Agent 可以自主完成的事项**：数据采集、风险判断、预警推送、基础工单下发
- **Agent 必须先询问的事项**：订单等级、特殊交付要求、赔付接受范围
- **Agent 必须交由人工处理的事项**：核心订单决策、大额赔付调整、极端风险处置
- **Agent 不允许做的事项**：私自修改订单条款、直接对外签订追责协议
- **高风险操作的限制条件**：对外文书需人工审核，最终方案必须人工确认
## 9. 资料与工具

- **使用的资料来源**：ERP、采购、生产、客户、供应商管理系统
- **可读取的知识库**：交付标准、赔付规则、协同流程、预警阈值
- **可操作的外部工具或 API**：各系统数据接口、办公消息推送接口	
- **权限范围「工具的输入/输出限制」**：仅可读数据，无修改权限；敏感信息做脱敏处理
- **资料更新频率**：物料数据实时同步，其余数据定时刷新
- **敏感资料处理规则与「延迟要求 (Latency)」**：客户信息、订单价格、供应商合同条款等敏感数据，需脱敏后再用于分析；物料预警推送延迟≤1分钟；订单风险评估完成延迟≤5分钟；数据查询接口响应延迟≤3秒。


## 10. 失败与兜底

- **模型不确定时的处理方式**：暂停自动决策，提示补全信息并转人工
- **资料不足时的处理方式**：暂停自动决策，提示补全信息并转人工
- **最大重试次数与死回圈中断机制**：同一问题连续提问 2 次后停止，输出当前已有分析结果
- **工具失败时的处理方式**：自动重试，失败后记录日志并提醒人工介入
- **使用者拒绝建议时的处理方式**：记录操作，按人工方案重新执行
- **需要转人工的条件**：核心订单、大额风险、数据冲突、极端事故
- **错误提示与恢复方式**：风险评估错误、误判订单处理方案的占比

## 11. 评估指标

- **任务完成率**：：物料延误场景下，风险评估与协同工单生成的完成比例
- **正确率**：订单履约风险评估结果与人工最终决策的一致性
- **平均完成时间**：从物料预警触发到决策建议推送的平均耗时
- **使用者满意度**：生产、采购、订单部门对AI Agent的使用满意度评分
- **人工介入率**：需要人工确认/接管的订单决策占比
- **评审通过率**：分析报告通过结构化评审的比例
- **口径引用率**：输出中正确引用口径字典版本号的比例

## 12. 验收标准

- **功能验收标准**：数据抓取、风险评估、协同工单生成、预警推送功能正常运行，无报错
- **效能验收标准**：订单违约率、停工时长、跨部门沟通成本下降达到预设目标
- **安全与权限验收标准**：敏感数据脱敏处理，权限控制符合要求，无数据泄露风险
- **边界案例验收标准**：核心客户订单、数据缺失、工具失败等场景下，能按规则触发人工介入流程
- **上线条件**：功能测试通过、数据对接稳定、权限配置完成、用户培训完成


## 13. 风险与依赖

- 技术风险：多系统数据对接不稳定，数据延迟/缺失导致风险评估偏差
- 产品风险：使用者仍依赖人工处理，系统使用率低，无法落地
- 法务或合规风险：自动生成的供应商追责函、客户通知存在合规问题
- 内部资料依赖：ERP、采购、生产等系统的数据质量与稳定性直接影响效果
- 外部系统依赖：依赖ERP、采购、MES、CRM等系统的实时数据接口，数据质量与稳定性直接影响决策准确性
- 依赖企业微信/钉钉等办公工具，推送预警与协同工单的及时性
- 缓解方案：技术侧：建立数据备份与重试机制，接口异常时自动降级为人工数据录入通道
- 业务侧：定期同步数据标准，建立人工兜底的应急预案，避免系统故障导致业务停摆
- 权限侧：配置分级权限，关键操作必须人工审核，降低系统依赖风险
