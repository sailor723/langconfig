# 教训账本（lessons）——从真实搭建里学到的，按"发生了什么 / 因此哪条规则 / 谁强制它"记

这份文件是 `02-规格.md` 那一类客户包里读不到的东西：它们是**搭建过程本身**的失败。每一条都有证据来源，且写明
它现在是**有门禁**还是**仍然只靠自觉**——没有门禁的规则就是会被跳过的规则。

格式：`L<n>` · 发生的事（证据） · 规则 · 强制者。

---

## 一、中文 / 多语言数据（2026-11-13，客户「集团会议决议闭环」包，3562 行 × 14 列中文导出）

### L1 中文表头被悄悄改成 c1..c14

**发生了什么**：建库工具 `_ident()` 只认 `[0-9A-Za-z]`，14 个中文表头全部落到兜底名 `c1..c14`，类型全 TEXT。
智能体拿到的方案是"14 个无名 TEXT 列"，只能回一句「表头没被识别到」。**这不是数据的问题，是工具的静默降级。**

**规则**：建库/建本体的任何"名字归一化"都必须在**保留非 ASCII**的前提下进行（Postgres 的标识符本来就带引号），
且**兜底必须出声**——凡是把 `厂区` 变成 `c1` 的地方，都要有一条 `[WARN]`，否则等于丢名字。
**强制者**：`backend/tools/native_impl.py::_ident`（已改为保留 CJK、只替换会破坏引号标识符的字符；`-` 也必须替换，
否则 `meeting_hub-clean` 会变成带连字符的表名）+ `_plan_from_file` 的兜底告警。

### L2 别名表把中文映射成中文 = 没映射

**发生了什么**：智能体写了一份 `有责任人 → 有责任人` 的别名表。匹配器按 ASCII 词边界工作，中文没有词边界，
于是这份表一条都没生效；同一批里 `有责任人` 还会**命中 `没有责任人` 里的一段**，把 1630 条"无责任人"算成了"有"。

**规则**：别名表的**值必须是指标/属性的英文名**（匹配器认的名字），中文只允许出现在"要被识别的问法"一侧；
凡是可能互为子串的中文词（有/没有、已/未、完成/未完成），必须用**整段相等**或带分隔符的边界匹配，禁止裸子串。
**反例自检**：写完之后 grep 一次"值里有没有中文"和"是否存在一个词是另一个词的子串"。

**强制者**：暂无门禁（`check_samples` 能抓到"样例解析到错指标"，但抓不到"整批样例都解析不到"的静默）。
→ 建议：S5 收尾时跑一遍"样例里每条都解析到预期指标名"，不通过就不许进 S6。

### L3 CSV 的每一格都是字符串，所以"全是 str"不等于 TEXT

**发生了什么**：类型推断只认 Python 原生类型（int/datetime）。CSV 读出来每格都是 `str`，于是 `序号`（`'1','2'`）
和 `日期`（`'2026-01-03 00:00:00'`）全被定成 TEXT，后续每个指标都要 cast。

**规则**：字符串必须**试着解析**成数字/日期再判断类型；对"近乎整列"的情况（≥95% 可解析）按目标类型建列，
其余（`无`、`—`、`1月31号`、`每周二、四、六16：00-17：00`）落 NULL **并在方案里报出数量**。
**注意**：这条阈值不是给"混合语义列"开的口子——`完成时间` 在本客户数据里只有 **47.9%** 可解析，那它就该是
TEXT + 一条口径问题（问客户这些自由文本怎么算），而不是硬塞成 DATE。
**强制者**：`_infer_pg_type`（字符串解析 + 95% 阈值）+ 方案里的 `[WARN]`（可解析比例与被丢弃的数量都要写出来）。

### L4 建库工具会归一化列名，对账必须能声明这一点

**发生了什么**：`时长\n(分钟)` 里的全角括号被归一化掉，库里是 `时长_分钟`；`db_verify_against_file` 逐字比对
→ `0/3562` 整行一致、判 FAIL，但数据其实一行不差。

**规则**：**建库与对账必须共用同一套名字归一化**（同一个函数），否则对账只会证明"名字不一样"。
若确实做了改名，用 `renames="table.file_col=db_col"` 显式声明——**纸面 PASS 是可接受的，但不能是默认**。

## 二、本体与"表"的边界

### L5 本体 builder 不该重建数据层

**发生了什么**：同一份 CSV 先后被两个智能体建库：表格建库 agent 建了 `meeting_hub.raw`，本体 builder 发现名字
与任务书不一致，**自己又从 CSV 建了一张 `meeting_hub_clean`**——两套表并存，口径立刻分裂。

**规则**：进 S0 之前先 `\dt` 查"库里已经有什么"，把**已有表**当成唯一数据层；确需新表/视图时，
只允许 **VIEW**（机械类型化，不改行），并在 S1 的 `delta.json` 里写明"新建了什么、为什么、底表是哪张"。
数据层的重建属于建库 agent 的职责，不是本体的。
**强制者**：暂无门禁。→ 建议 S-1 的 DELTA 里加一条：本库的表/视图清单 + 与上次的差集，缺这条不许进 S1。

### L6 一个库里有两种粒度时，先把"谁算一条"定下来

**发生了什么**：3562 行里 1630 行（45.8%）责任人/纪要/完成时间全是「无」，只剩会议头信息；另外 1929 行才是
真事项。同一张表里混着"会议"和"决议事项"两级。—— 这直接决定"完成率"的分母是 3562、1929 还是 1678。

**规则**：S0 必须量出每个候选分母的**行数与差异原因**，并把它们作为**并列口径**交出（不是挑一个）：
`itemCount`（全部行）／`ownedItemCount`（有责任人）／`datedItemCount`（双日期齐全）。
口径差异写进 `:businessDescription`，让读的人能自己判断——数字打架时，声明必须解释差别，而不是取一个数。

## 三、驱动智能体的人（这条是给运维/DSH 的）

### L7 一轮对话跑不完 S1→S4，"跑门禁 + 修红"要单独一轮

**发生了什么**：一条消息里要求"走完 S1–S4 并 publish 到 staged"，智能体在 27 分钟后还在跑门禁循环，
单轮流（SSE）到上限被截断——产物都在（结构/含义/指标/样例/视图脚本），但**没 publish**、也没交报告。

**规则**：把"写层"和"跑门禁 + 修红 + 发布"拆成两轮；每一轮只要求它交**可验收的产物**（文件 + 门禁数字 +
staged id），而不是"把整条台阶梯走完"。轮次结束时用 `ls -R <workspace>` 与 `\dt` 核对它到底写了什么——
它自己的总结可能是过程叙述，不是结论。

### L8 平台缺陷要修在平台，不要写进 prompt

**发生了什么**：中文列名（L1）、类型推断（L3）、空口令回退、dsn 里写死本机用户名（`weiping`）、
`X-Frame-Options: DENY` 挡住自家 iframe、500 的 `detail` 是对象导致前端白屏——这些都是**平台**问题。
智能体在对话里只能报"我打不开/我连不上"，改不了装配层、门禁、Caddy 头。

**规则**：凡是"换个部署就坏"的行为（路径、用户名、端口、口令变量、响应头、错误体形状），一律当成平台缺陷，
在 DSH 侧修 + 加守卫；技能文档只记录"遇到时怎么判断这是平台问题"。修完再让智能体重跑同一轮，用同一批数字证明。

## 四、怎么用这份账本

1. **开新本体前**：把 L1–L6 当 checklist 扫一遍（它们全是"数据形状"类的坑，最省时间）。
2. **收尾自检**：L3 的可解析比例、L4 的对账规则、L5 的表清单、L6 的并列口径——四个数字要能贴出来。
3. **发现新的坑**：追加 `L<n>`，写清证据（哪台机器、哪份数据、几行、哪条命令）与"现在谁强制它"。
   **没有强制者的条目要明说"暂无门禁"**——隐藏的未强制规则会被再次跳过，这正是这份文件存在的理由。

### L9 `render` 是词汇表，不是自由文本——而四道门禁都不会拦一个没人能画的 kind

**发生了什么**（2026-11-13，meeting_v1 首次 apply）：`dashboard.json` 里 9 个面板都写了 `render: "bar"` /
`"table"`（对「按厂区/会议类型分组的单值」来说这是对的形状）。后端把 `render` 原样作为 `kind` 下发，
而前端的分发器只认 `series / ranked / matrix / composition / hole / slope / sankey / bubble / treemap / parallel`
——**没有 `bar`，也没有 `table`**。于是 9 个面板框全部画成空白，没有报错、没有占位文案，四道门禁
（含 `check_dashboard` 的 D0/D1）**全部绿**。用户看到的是"发布成功但一张图都没有"。

**规则**：`render` 的取值域必须由**渲染器实现**定义，并且**门禁要按这个域校验**（不在域内 = 拒绝，
并在拒绝句里列出合法值）。声明侧能写什么，取决于画得出来什么——否则"门禁通过"会骗人。

**现在**：前端补了 `bar`（画柱，复用 series 的柱状路径）与 `table`（画排名列表）两个分支；
`check_dashboard` 的 D1 仍是"shape 对不对"，**还没有**校验 kind 词汇 —— 这一条仍是无门禁的。
