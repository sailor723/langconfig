你负责**在交付之前把工作自证一遍**。你的产物不是一份说明，而是**一串能重跑的证据**。

这个技能只有一条底层判断：**东西"看起来对了"不算完成，能被人拿一条命令复现才算完成。**
下面六步，每一步都对应一次真实交付里发生过的失败。

## 第 0 步——先证明环境，再动手

在写任何文件、跑任何查询之前：

```bash
command -v psql && psql "$DATABASE_URL" -c 'select 1'      # 连接真的通吗
<解释器> -c 'import rdflib, sqlalchemy; print("ok")'        # 依赖真的在吗
ls <技能或仓库里点名的路径>                                  # 路径真的存在吗
```

**为什么**：实测的一次构建里，技能和用户给的路径两处都是错的（`backend/retail_graph` 不存在、`backend/.venv`
里没有 `rdflib`），靠两轮 `ModuleNotFoundError` 才定位。而那次失败**还被管道吞掉了**——见第 4 步。

## 第 1 步——数字先跑后写，写不出就写「未测量」

任何要进文件的数字，**先贴一条产出它的查询**，再写进文件。顺序反了就是在编数字：

- 反例（实测）：先把 `"43,244 站"`、`"43,244/51,210 = 84.4%"` 写进 `metrics_ext.ttl`，**79 秒后**才跑
  `select on_time, count(*) ...` 得到 `47920 / 3290 / 93.6`。而 `43,244` 在整段 260 次调用里**第一次出现就是
  那次写文件的正文**——不是查出来的，也不是算错的，是编的。
- 正确：先 `select`，把结果贴进对话，再写文件；改完用 `grep -n '<旧数字>'` 确认没有残留。

写不出来的数字，正文写 `未测量`，不要写一个"看起来合理"的估计。

## 第 2 步——写盘之后，让 shell 看见它

工具的"成功回执"**不是证据**，能 `wc -l` 到才是：

```bash
wc -l <刚写的文件> && head -3 <刚写的文件>
```

实测的三种假成功：工具回 `Updated file …/ontology/01-structure.ttl` 而同一秒 `wc` 回 `No such file`；
长内容的写调用把 `file_path` 弄丢了（参数里只剩 `content`，`result` 为空）；落盘落进了镜像树 `./Users/...`。
三次都被下一条命令抓出来——所以下一条命令必须在。

## 第 3 步——每条门禁都要说出「能把它变红的变异」

对每一条检查，回答：**我改哪个东西，这条检查会失败？** 说不出 → 标 `Ungated`，别写得像已经强制。

能说出的，还要再分一层：**`RED`** 还是 **`RED for the wrong reason`**。

- 实测：变异 `M2` 声称能暴露"重复列"缺陷，但编译器根本没有编译期歧义守卫——重复列是**数据库**拒的，所以
  `M2` 复现不了它声称的东西；
- 同一套门禁用 `"RED," in output` 计数，把 `"M1 drop :references -> RED for the wrong reason"` 也算成红，
  于是计数器一直卡在 `3/4`；改成 `"-> RED" in output and "wrong reason" not in output` 才 `14/14 PASS`。

**一条因为错误原因变红的检查，下一次仍然会给你假绿灯。** 交付时把 `Ungated` 与「只验过形状」的条目点名列出。

## 第 4 步——读退出码，不要读最后一行

实测：`... | tail` 把失败吞掉，`ModuleNotFoundError: No module named 'psycopg2'` 与
`[Command succeeded with exit code 0]` 出现在同一段输出里；`status` 字段更是 260/260 全 `completed`，
其中 8 条是超时、`No such file`、SQL `ERROR:`。

规则：**判失败看文本标记**（`[Command failed`、`timed out`、`Traceback`、`[stderr]`、`No such file`、
`command not found`），不看退出码的最后一行，也不看工具自报的状态。要引用结论时，引用那段能看见标记的输出。

## 第 5 步——「编译得出来」不等于「答得了」

同一个概念，分别走三条路，三者不一致就是 bug，不是数据问题：

1. **编译**（编译出 SQL、门禁通过）；
2. **推理通道**（自然语言问题能不能被选中并回答）；
3. **HTTP / 端点**（真正对外的那条路）。

实测：两个**答得了**的问题被推理通道判成"拒绝"（`:OverloadedTrip` 只有 `:physicalPredicate` 没有基数对象），
而 samples 门只数「拒得有没有名字」（`0 refuse unnamed`）——**错拒在门禁里是绿的**。

另一头也实测过：自检脚本把**对象名**送进只接受**定义类**的端点，得到 6 条假拒绝。检查量错了对象，比没有检查更贵。

## 第 6 步——交付时说三件事

1. **能做什么**；
2. **不能做什么**——把拒绝清单原样念出来；
3. **证据强度**：哪些数字来自哪条查询、哪些检查有变异、哪些标了 `Ungated`、哪些是 `未测量`。

第三件不是免责声明，是交付物的一部分。不报它，等于把推测伪装成经验。

## 拒绝清单（硬契约）

- 不在没有查询结果的情况下把数字写进文件或报告；
- 不把工具的"成功回执"当成文件存在；
- 不把「门禁全绿」当成「结果正确」——除非每条门禁都说得出变异；
- 不给一个错拒（该答却拒）记绿灯；
- 不用自己维护的名单当自检分母，分母取端点返回的实数；
- 不因为一次通过就宣布可复现——**能重跑才算**；
- **不在回合里重启/杀掉承载你这个回合的服务**：你多半是被它调用起来的，重启它等于把自己的证据链和整段对话一起弄没
  （见 `references/pitfalls.md` 的 P7）。要重启就把命令原样交给用户。

## 边界（由宿主/智能体提供）

- **shell**：环境证明、写盘核对、门禁、查询都要真的执行；
- **一个只读数据库连接**：数字的来源必须是真数据；
- **能跑门禁的解释器**：拿不到就明说，不要用"应该没问题"代替。

缺任何一项，本技能不承诺交付，只承诺一份「做了什么、缺什么」的清单。

## 参考

`references/pitfalls.md` 收着**宿主层面**的坑（虚拟文件系统镜像、结果被截断、状态字段造假、单次执行超时）。
它们换一个宿主就作废，所以不写进上面的步骤——但它们会让"成功"看起来像真的，读一次能省一轮排查。
