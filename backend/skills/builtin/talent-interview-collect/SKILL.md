你负责**给一个人打这一轮电话**，然后把回答落成 `work/talent/cv_interview/<候选人>.yaml`。

## 第 0 步——先拿到"这个人缺什么"

```bash
cd <repo>/backend && set -a && source ../.env; set +a
env -u PGPORT .venv/bin/python -m scripts.talent.build_collection_spec \
    --jd <JD> --candidate "cand_<候选人>"
```

产物 `work/talent/collection/<JD>.<候选人>.一面脚本.md` 会告诉你三件事：
还缺哪几条、每条问什么、**答案要落成什么字段**。只问缺的 —— 已经不缺的不占面试时间。

## 第 1 步——问法

- 沿着 JD 原话问，但**不要把 JD 念给候选人听**（那是让他背答案）
- 要听具体的事，不是"会不会"：「用过没有、上一次用是什么时候、你在其中负责哪一段」
- 每得到一个回答，立刻想清楚它落成什么：一个数？一个属性？一个组件？

## 第 2 步——落盘：三种落法，必须显式写

```yaml
answers:
  - field: F.EDU_LEVEL            # 落进哪个档案字段
    props: {education_rank: 3}    # 直接定值（属性）
    question: 三段学历分别是什么层次？
    answer: 广东司法学校中专；东莞职业技术学院大专；暨南大学自考本科
    note: 简历只写了校名，没写层次

  - field: F.EXP_ACTIVITY
    establishes: [skill_客户验厂]   # 这条回答坐实了哪个组件
    question: 「熟练应对二方与三方审核」是客户来厂审，还是你审供应商？
    answer: 客户来我们厂是主要的，日系每年一次，从首次会议到整改关闭都是我接待
    note: 简历那句话读不出角色，只有问才知道
```

**`establishes` 必须由你（采访人）写，不许程序推测。**
原因是「熟练应对二方与三方审核」这句话读不出"被审还是审人"——
映射到哪个组件是一个采访判断，不是文本相似度能算的。

## 第 3 步——三条硬规矩

1. **来源要分开**：简历原文是 `resume`，这场对话是 `interview`。
   混成一个来源，出了问题查不出是哪一环 —— 简历错了是简历的事，访谈错了是我们记录的事。
2. **不许把候选人说的话写成简历原文**。他没写在简历上的，来源就是 interview。
3. **没有刻度的东西不要安刻度**。「口语一般」就记「口语一般」，不要换成「B1」。
   换成等级只是让它看起来可算，实际上是假精度。

## 第 4 步——收尾：报缺口，分责任

问完再跑一次第 0 步的命令，报：

- 这个岗 N 条要求里，现在**够了几条、还缺几条**
- 每条缺口**是谁的责任**：
  - 候选人没说清 → 下一轮补问
  - 客户没给阈值（比如薪资预算、上班地点还没定）→ 找客户，问候选人没用
  - 模型没有可判的数据项（E 维素质类）→ 这类永远判不了，只能进"人看的部分"

最后一种要说清楚：**这类要求不是"没问到"，是"问了也算不出来"**。

## 绝对不要做

- 不要问已经不缺的项（浪费面试时间，也让候选人以为我们在走过场）
- 不要把回答写成一段自由文字（问完落不进字段，等于没问）
- 不要自己推测 `establishes` 的映射
- 不要给主观判断安一个数字（那是 4b 的事，而且不进计算）
- 不要漏掉"答案格式"那一栏：每条答案都要能写进同一个字段，否则问了也用不上

## 交付前回检（**不许跳**）

写结论之前,把**打算写进报告**的每个数字现场重算一遍,并把命令贴出来。

```bash
cd <repo>/backend && set -a && source ../.env; set +a
env -u PGPORT .venv/bin/python -m scripts.talent.build_collection_spec \
    --jd <JD> --candidate "cand_<候选人>"
env -u PGPORT .venv/bin/python -c "import yaml,sys; d=yaml.safe_load(open('../work/talent/cv_interview/<候选人>.yaml',encoding='utf-8')); print('答',len(d['answers']),'· review',bool(d.get('review')))"
```
**"够几条/缺几条"必须是脚本最后一行原话**,不是你的复述。

### 为什么必须跑

我交过一份报告,里面真话和假话同时存在:
门禁 161 checks 全绿(真)、HermiT 影响面 114→108→99(真),
但「`_source` 7 行」(实际 48)、「有一行含『主导内审』」(这份 JD 没有)、
「excluded 是抬头标题」(实际是 IATF16949)—— **三句假话**。

它们有同一个来源:**从记忆里写**,而记忆来自另一份 JD 或上一轮。
所以规矩是:**每个数字现场重算,每句"原文有 X"现场 grep。记忆不算证据。**

### 三条自查

1. 这个数字我是刚跑出来的,还是记得的?—— 记得的一律重跑
2. 这句话我能指出在文件的哪个位置吗?—— 指不出就是没读
3. 我是不是把**别处**的内容混进来了?—— 报告里的每一句,都要能在**这一份**产物里找到

### 两条"看着像绿的红"

- **门禁没有汇总行 = 没跑完,不算通过。** 一处 YAML 写坏会让门禁中断,
  而它前面的 PASS 已经打印了 —— `tail` 看着完全正常。只认 `N checks · M failed` 那一行。
- **写完不等于写对。** `write_file` 成功之后必须重跑校验,不能凭"它没报错"。
