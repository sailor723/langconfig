# T1 · 单 agent

> 提炼自：案例 1（281）、案例 2（159）、案例 3（326）· 事实见 `facts/case-facts.md`
> 模板只写本结构独有的段落；通用规则（读目录、命名、交付）在 `../SKILL.md` 和你的系统提示词里。

## 1 适用场景

用：一个职责、一套工具、输入输出都是文本或文件。
**不要用**：需要按阶段换提示词（→ T3）、需要多个专家分工（→ T2）、需要写多步报告（→ T5）。

判据一句话：**能在一次对话里把活干完，且工具互不冲突**。

## 2 配置骨架

```json
{
  "name": "{{slug}}",
  "kind": "normal",
  "category": "{{category}}",
  "description": "{{一句话：做什么 + 产出落在哪}}",
  "model": null,
  "temperature": 0.0,
  "native_tools": ["{{tool1}}", "{{tool2}}"],
  "skills": [],
  "subagents": [],
  "middleware": [],
  "system_prompt": "{{见第 3 段}}"
}
```

`kind` 默认 `normal`：平台会补 guardrails 和工具强制约束。只有需要 harness 自带的
`ls/read_file/write_file/glob/grep`（不显式配置就能用）时才选 `deep`——12 个案例里
只有 2 个是 deep，别默认选它。

## 3 提示词骨架

只写四段，别写第五段：

```
你是 {{角色}}。{{一句话职责}}。

## 输入
{{用户会给什么；没有时怎么默认}}

## 怎么做
1. {{第一个动作，通常是一次工具调用}}
2. {{第二个动作}}
{{工具用哪一个、失败怎么办——写死，别让模型自己挑}}

## 产出
- 写到 generated/{{文件名}}，格式 {{md|csv|…}}
- 回答里给 {{温度/结论}} + 一行文件路径，不超过 {{N}} 行

## 边界
- 不处理 {{无关请求}}，一句话说明
- 查不到就说查不到，不许编数字
```

**反例**（案例 2 的 3,426 字能力清单）：把「你能用哪些工具」抄进提示词。工具目录在
schema 里，模型看得到；提示词只该写**什么时候用哪个**。

## 4 工具与 middleware

| 项 | 必选 | 说明 |
|---|---|---|
| 工具 | 2–4 个 | 超过 5 个先问：是不是该拆成 T2 |
| `write_file` | 要落盘才选 | normal agent **不带**自带文件工具，必须显式选 |
| `read_any_file` | 要"写完回读校验"才选 | **deep agent 在本平台拿不到 `read_file`**：harness 只给 `ls/glob/grep/write_file/edit_file/delete`。回读内容用 `read_any_file`，或只用 `grep` 做行级核对 |
| middleware | 无 | 这个结构不需要；要审批再挂 `hitl`（→ 见 T2 第 4 段） |

最小够用集合，别照抄满配：案例 1 用 3 个工具就够，案例 2 的 27 个是反面教材。

## 5 rubric 模板

```
R1 工具命中：探针里出现过 {{tool1}}（tool sequence 里有它的名字）
R2 产出存在：generated/{{文件名}} 存在，且含 {{必备字段}}
R3 数字有据：回答里的 {{数字}} 与工具返回一致，或标了来源 URL
R4 边界：问 {{无关问题}} 时明确说不处理，不硬答
```

## 6 实测基线

- 案例 1：3 工具，同题 8.1s；案例 2：27 工具，同题 11.5s → **工具数本身就是延迟**
- 案例 3：3 个只读工具（`glob/grep/read_any_file`），无需 middleware

## 7 失败对照

| 症状 | 原因 | 改法 |
|---|---|---|
| 不调工具直接答 | 提示词没说"必须先查" | 第 3 段第 1 步写成硬动作 |
| 调了工具但答案里没数字 | 产出契约缺字段 | 第 3 段「产出」写死字段名 |
| 该落盘却没文件 | normal agent 忘了选 `write_file` | 第 4 段 |
| 越权（能跑 bash/执行代码） | 照抄了满配工具集 | 回到最小够用集合 |
