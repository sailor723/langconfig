# EBL OS（team-2）数据集分析 —— 从一份经营方案到可核查的库

来源：`client/team-2/11 亿营收目标与防御性毛利守护方案.MD`（197 行，经营方案，**不是**软件项目、**不是**数据导出）
性质：这是"先有故事、没有数据"的典型 —— 方案里每个数字都是**断言**，数据集的任务是让这些断言可被查询证伪或证实。

---

## 0. 一句话

东莞某传统眼镜制造企业，约 2 800 人，去年营收 9 亿、今年目标 11 亿（+22%），原希望毛利 20%+；
盘问后确认"规模与高毛利不可同时达成"，于是转为**防御性策略**：守 11 亿、接受加权毛利 18–19%、
全年硬地板 17.5%、季度预警 17%，用低毛利订单填产能（≤25%，且只喂利用率 <70% 的产线）。

---

## 1. 从故事里读结构（不读形容词）

| 简报里的句子（§出处） | 变成什么 |
|---|---|
| 「约 2800 人，设销售、研发、生产、行政、人事、财务等部门」（§二） | `employees(2800)`，`department` 落在这 6 个部门 + 少量支撑岗 |
| 「去年营收 9 亿，今年目标 11 亿」（§一） | 财年切成 FY2025 / FY2026 两个 regime，`orders.order_date` 覆盖两年 |
| 「Q1 2.5 亿 / Q2 2.7 亿 / Q3 2.9 亿 / Q4 2.9 亿」（§四） | `orders` 的季度营收分布，四条**可查询的等式** |
| 「加权毛利目标 18–19%，全年硬地板 17.5%，季度预警 17%」（§一、§四） | `order_lines.gross_margin` + 加权口径（按营收加权），三个阈值写成三条不变量 |
| 「产品分级定价：差异化品 25–28%、标准品 15–18%、低毛利走量 13–16%」（§四） | `products.tier` 三档 + 每档毛利的**区间**不变量（这是客户会拿去核对的数字） |
| 「低毛利订单仅限利用率 <70% 产线，双签、提成减半、6 个月复审、全年 ≤25%（约 2.75 亿）」（§四） | `production_lines.utilization` + `order_lines.tier='低毛利走量'` 的**约束**：零违规 + 营收占比 ≤25% |
| 「B 新客户 0.6–0.8 亿；C 微改良 0.3–0.4 亿；A 老客户加购 0.2–0.3 亿」（§四） | `order_lines.growth_bucket`（A/B/C）+ 与 FY2025 的增量对比，三档**区间**不变量 |
| 「核心客户清单：销售副总 + 财务总监联合提出，总经理拍板，Q1 锁定，全年不轻易调整」（§七） | `core_customers` 表 + `locked_at`；流失 = FY2025 有单、FY2026 无单，不变量 ≤2 家 |
| 「四维分级：毛利率、年采购额、回款准时率、比价拖账行为，3 项以上落 A 档 → A 类」（§六） | `customers` 上四个维度列 + 由它们推出的 `segment`，并留一条**可复算**的判档 SQL |
| 「华南大区试点 → 规则定稿 → 全公司推开，第 3 周 A/B/C 定义文件双签」（§六） | `customers.segment` 在 2026-03-20 之前为 **NULL**（未分级），之后才有值 —— 制度切换点是一个 regime |
| 「前 10 大原材料供应商集中议价、采购成本降 3–5%」「行政部 Q1 冻结非生产性支出」（§八） | `suppliers`（含前 10 标记、付款账期、FY2025/FY2026 采购额）+ `opex_items`（可冻结/不可冻结） |
| 「微改良 3–5 个改进点，出口检测认证 1–2 项，认证溢价 2–3%」（§三、§四） | `products.tier='微改良'` + `certification_premium`；认证只挂在微改良上（不变量） |
| 「17 个任务、四批、任务 1 进行中」（§五、§六） | **不进库**：这是执行计划，不是业务事实。任务状态属于项目管理，不属于数据集 |

**不读的东西**：「议价能力低」「研发不能引领」「交付能力较差」「运营成本太高」这些形容词不是列 ——
它们是**结论**，要由列算出来；算不出来就进拒绝清单（见 §4）。

## 2. 实体 → 粒度 → 体量

| 表 | 一行是什么 | 体量 | 为什么是这个数 |
|---|---|---|---|
| `customers` | 一个客户（含分级四维与 A/B/C） | **180** | 11 亿营收 / 年均 610 万 ≈ 180 家；客户数与"核心客户 ≤2 家流失"才可测 |
| `products` | 一个 SKU | **420** | 眼镜制造：三档产品 × 镜架/镜片/配件 × 系列；够分出"差异化/标准/低毛利/微改良" |
| `orders` | 一张订单（客户 × 下单日） | **≈2 400** | 11 亿 / 单均 460 万 ≈ 2 400；一年 250 工作日 ≈ 每天 10 单，符合"小批量快反"的痛点叙述 |
| `order_lines` | 订单的一行（一个 SKU 的交付批次） | **≈9 600** | 每单 4 行；毛利率、档位、增长来源都落在这一层（不是订单头） |
| `production_lines` | 一条产线 | **32** | "关停/合并利用率最低产线"需要有可数的产线；30 左右才排得出"最低 3 条" |
| `suppliers` | 一个原材料供应商 | **40**（其中 10 家标 `is_top10`） | §八"前 10 大供应商"直接点名 |
| `employees` | 一名员工 | **2 800** | §二点名的 2 800 人，按 6 个部门分布 |
| `core_customers` | 核心客户清单的一行（锁定快照） | **12** | §七"Q1 锁定、全年不轻易调整"；12 家正好让"≤2 家流失"有区分度 |
| `micro_improvements` | 一个微改良/认证项目 | **5** 改进点 + **2** 认证 | §三"3–5 个微改良点"、§四"认证 1–2 项" |
| `opex_items` | 一条非生产性支出科目 | **28** | §八"行政部 Q1 冻结非生产性支出，出清单" |

**事实层只有一个可加粒度**：营收、毛利、数量都落在 `order_lines`；`orders` 只是分组键，
`customers`/`products`/`production_lines` 是维度。任何"按客户/按档位/按季度"的数都必须能回到 `order_lines` 求和。

## 3. 不变量（每条都是一条 SQL，绿=数据仍然说着方案说过的话）

写成 `backend/skills/builtin/generate-mock-dataset/fixtures/ebl_ops/ebl_ops.dataset.json`，由 `check_dataset.py` 执行。核心 14 条：

1. **FY2026 营收 = 11.0 亿**（±0.5%）；
2. **FY2025 营收 = 9.0 亿**（±0.5%）—— 增量才有意义；
3. **季度营收** = 2.5 / 2.7 / 2.9 / 2.9 亿（各 ±3%，合计=11 亿）；
4. **FY 加权毛利率 ∈ [18%, 19%]**（按营收加权，不是行平均）；
5. **每个季度加权毛利率 ≥ 17%**（季度预警线，任一季破线即红）；
6. **低毛利走量档营收占比 ≤ 25%**，且 ≤ 2.75 亿；
7. **低毛利订单只出现在利用率 <70% 的产线**（违规数 = 0）；
8. **三档毛利落在方案给的区间**：差异化 25–28%、标准 15–18%、低毛利 13–16%；微改良 25–28%；
9. **认证溢价只挂在微改良产品上**，且 ∈ [2%, 3%]；
10. **增长三桶**：A 老客户加购 0.2–0.3 亿、B 新客户 0.6–0.8 亿、C 微改良 0.3–0.4 亿（与 FY2025 对比的增量）；
11. **核心客户流失 ≤ 2 家**（FY2025 有单、FY2026 无单的核心客户）；
12. **员工 2 800 人**，且 6 个部门都有（销售/研发/生产/行政/人事/财务）；
13. **产线利用率与低毛利订单的对应关系成立**：利用率 ≥70% 的产线，低毛利订单营收 = 0；
14. **sum(order_lines.revenue) = sum(orders.revenue)**（父子恒等式，任何一层口径都回到同一批钱）。

### 有意放进去的数据病理（否则数据集教错误的课）

| 病理 | 机制 | 谁会被它绊到 |
|---|---|---|
| **未分级的客户** | `customers.segment` 在 2026-03-20（规则双签）之前为 NULL；约 18% 的客户到年底仍未分级 | "按 A/B/C 算占比"必须声明分母；否则 100% 的份额里混着一批没判定的 |
| **回款准时率缺失** | `customers.on_time_payment_rate` 约 12% 为 NULL（新客户、停止合作客户） | 四维判档的第三维不可判定 → 分级要写"缺失如何处理" |
| **比价拖账是文本不是评分** | `customers.price_compare_behavior` 是离散文本（`无`/`多次比价`/`拖账 30+ 天`/`拖账 90+ 天`/NULL），不是 0–100 分 | 想算"四维打分"就得先定文本→分档规则，这是**业务决定**，数据集不替它答 |
| **两套营收口径** | `orders.revenue`（订单头总价）≠ `sum(order_lines.revenue + adjustments)`（有折扣/返利行）——差额约 1.5% 落在 `order_adjustments` | "11 亿"用哪个口径？两条路线都要能跑，差值必须被解释而不是抹平 |
| **核心客户清单是快照** | `core_customers` 只有 `locked_at` 一个版本，FY2025 的"核心客户"无从得知 | "核心客户流失"只能按 FY2026 的清单向前追，谁在 FY2025 是核心**不可知** → 本体应按名拒绝 |
| **一条缺账期的供应商** | 40 家里 1 家 `payment_days` 为 NULL | "议价/账期重谈"的可算范围要声明 39/40 |

## 4. 这份数据**不能**回答什么（拒绝清单，before the fact）

| 业务想要 | 为什么这份数据答不了 | 补什么才能答 |
|---|---|---|
| **议价能力指数** | 方案只说"议价能力低"，没有定义、没有一个可观测代理（如同样 SKU 的成交价 vs 市场价） | 需要"同 SKU 市场基准价"外部数据 |
| **引领性产品占比** | 方案明确放弃引领性产品（§三、§十），库里也没有"引领/跟随"标签 | 不补 —— 这是范围外，应该被按名拒绝 |
| **整体交付率** | 方案明确不追求整体交付率（§十）；库里有 `orders.promised_date`/`actual_date`，但**没有承诺条款等级**（核心客户 vs 普通客户），"交付率"口径无法唯一 | 补"客户级交付承诺"（SLA）字段 |
| **毛利率的构成（材料/人工/制造费用）** | `order_lines` 只有毛利额与率，没有 BOM 成本结构 | 补 `bom_costs`（材料/人工/制造费用三分） |
| **人员"不能快速缩减"的量化** | 只有 `employees` 快照与入离职日期，没有岗位可替代性与裁撤成本 | 补 `role_risk`（可替代性/裁撤成本）—— 且这属于人事敏感数据 |
| **产能利用率 <70% 的判定依据** | `production_lines.utilization` 是**方案口径给定的输入**，库里没有工时/节拍原始数据来复算它 | 补 `line_shifts`（班次工时、停机时间）后利用率才可复算 |
| **11 亿目标能否达成（预测）** | 数据集是 2026 全年的**实际发生值**（事后），不是预测输入 | 需要 `forecast` 事实上报 + 滚动预测表 |

## 5. 建库前必须由人拍板的四件事（技能 §0c）

1. **库名**：建议 `ebl_ops`（备选 `team2_ops`、`ebl_margin`）。
2. **币种**：方案里所有金额按 **RMB（元）** 理解 —— 确认。
3. **单位**：营收/毛利额用 `元`（库里另存 `万元` 展示），人数 `人`，利用率/毛利/占比 `%`（0–100 数值），订单量 `pcs`。
4. **PII**：客户名、供应商名、员工姓名一律**合成**（可读但不指向真实企业），不做掩码 —— 确认。
5. **时间窗**：FY2025-01-01 → 2026-12-31，时区 `Asia/Shanghai`，`as_of = 2026-12-31`（事后实际值，因此**相对窗口（最近 30 天）类指标应被拒绝**）。

> 这四条定了，就可以：`CREATE DATABASE ebl_ops` → 生成器落表 → 跑 `check_dataset.py` 把 §3 的 14 条全绿 → 交 manifest。
