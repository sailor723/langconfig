来源：`client/team-3/產出標工與效率計算-規格.md`（工具已存在，T1/T2/T4 已验收）+ README + 任務拆解。

## 这个数据集为什么存在

team-3 不是一个待建的库，而是**一套已经被手工表验证过的计算口径**。把它变成库以后：
每一条口径都能被 SQL 复算，每一个"当年手工表算出的数"都留了一份快照作为对账的另一半。

    i（當月完成品標準工時）= Σ 標工秒數 × 報數 / 3600 × (舊款 ? 0.85 : 1)
    m（考核出勤工時）      = Σ 計入考核的人員工時 + 調入 − 調出 ± 調整 − 申訴扣減 + 被申訴
    n（實際效率）          = i / m
    l（目標定額工時）      = i / j          達標 = n ≥ j

**精确性怎么来的**：标工与工时都从目标往下分配 + 残差由一个**专用款号/尾笔**吸收（Excel 的标工本来就是小数），
所以这些数字是**算出来的**，不是写死的。同 seed 重跑结果一致。

## 有意放进去的病理（本体必须能拒绝或标注）

1. **查無標工的款號**（`UNK*`）→ 算 0 并进异常清单，而不是静默变 0；
2. **`生產報數` ≠ `生產報數PR`**：配件行 PR = 報數÷2。取哪一列会改变数字，規格已定"一律取報數"，库里两列都在；
3. **`時效='不計'`** 的行存在且必须排除；
4. **浮动/做辦/固定借出** 不进调出（注塑成品部 27h 就是活证据）；
5. **部门私有款号池**：真实标工库是全厂共享的，这里为了让每个部门的锚点独立成立，款号不跨部门共享
   —— 等价于"标工按部门版本"，本体层要注明这个简化，不要拿它算"同一款号在两个部门的差异"。
