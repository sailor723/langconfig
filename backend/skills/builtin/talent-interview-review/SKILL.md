你负责**写出这一面的整体评语**，写进同一位候选人 yaml 的 `review:` 段。

## 第一原则：能变成要求，就不要变成评语

HR 说「我觉得他不太稳定」时，先问一句：**这个担心能不能落成一条可判定的要求？**

- 能 → 「近 5 年任职公司不超过 3 家」是一条要求，有阈值、能算、能回查。**退回 4a 去问，或者建议新增一条 HR 要求（带 rationale）。**
- 不能 → 「我觉得他态度一般」落不成要求，因为它没有数据项。这种才写进评语。

为什么必须这样分：评语没有刻度、没有出处、换个人写结论就变。
「沟通表达 4 分」说不清 4 分是谁定的。而要求即使判不了，也会诚实地落成「不可判」——
不需要另外发明一个刻度。

**所以：评语里不许出现分数、等级、星级、百分比。** 一出现，就是在把主观印象伪装成计算。

## 第 1 步——写三行，按这个结构

```yaml
review:
  heard: "他主动说上一家是主动离职，因为厂区要搬。问到时没回避，细节对得上。"
  basis: "工作经历 6 段、近 5 年 3 段、平均 3.6 年 —— 数据上不算频繁跳槽；离职原因问得具体，能复述。"
  reservation: "口语自评『一般』，没有客观刻度，只能按原话记；日系客户主要靠翻译，这一条我保留意见。"
```

- `heard`：我听到了什么（可复述的事实，不是判断）
- `basis`：我据此怎么判断，**带上数据或原话**
- `reservation`：我的保留意见 / 不确定的地方

三段都要有。只有 `heard` 没有 `basis`，读者没法判断你的判断靠不靠谱；
只有 `basis` 没有 `reservation`，等于声称自己全看透了。

## 第 2 步——哪些话不许写

- 「综合素质好 / 一般 / 较差」—— 没有依据的形容词
- 「感觉不太稳定」—— 如果真有依据，那就该是一条要求（见第一原则）
- 「建议重点考虑 / 不推荐」—— 这是决定，不是评语。决定由第 5 步和业务领导做
- 任何分数、等级、排名

## 第 3 步——明确写出"这份评语不进计算"

在 yaml 里写清：

```yaml
review:
  joins: false        # 明确：不参与 join，只随档案给业务领导看
  known_gaps:         # 这些是"问了也算不出来"的，不是没问到
    - "沟通协调能力：E 维无组件，判不了"
```

## 交付前回检（**不许跳**）

写结论之前,把**打算写进报告**的每个数字现场重算一遍,并把命令贴出来。

```bash
cd <repo>/backend && set -a && source ../.env; set +a
env -u PGPORT .venv/bin/python -c "
import yaml
d=yaml.safe_load(open('../work/talent/cv_interview/<候选人>.yaml',encoding='utf-8'))['review']
for k in ('heard','basis','reservation'): print(k, '=>', bool(d.get(k)))
print('joins =', d.get('joins'))"
```
三段都要在;`joins` 必须是 false;**全文不许出现分数、等级、百分比**(出现了就不是评语,是打分)。

### 为什么必须跑

我交过一份报告,里面真话和假话同时存在:
门禁 161 checks 全绿(真)、HermiT 影响面 114→108→99(真),
但「`_source` 7 行」(实际 48)、「有一行含『主导内审』」(这份 JD 没有)、
「excluded 是抬头标题」(实际是 IATF16949)—— **三句假话**。

它们有同一个来源:**从记忆里写**,而记忆来自另一份 JD 或上一轮。
所以规矩是:**每个数字现场重算,每句"原文有 X"现场 grep。记忆不算证据。**

### 三条自查

1. 这个数字我是刚跑出来的,还是记得的?—— 记得的一律重跑
2. 这句话我能指出在文件的哪个位置吗?—— 指不出就是没读
3. 我是不是把**别处**的内容混进来了?—— 报告里的每一句,都要能在**这一份**产物里找到

### 两条"看着像绿的红"

- **门禁没有汇总行 = 没跑完,不算通过。** 一处 YAML 写坏会让门禁中断,
  而它前面的 PASS 已经打印了 —— `tail` 看着完全正常。只认 `N checks · M failed` 那一行。
- **写完不等于写对。** `write_file` 成功之后必须重跑校验,不能凭"它没报错"。

## 交付时说什么

- 这份评语**不进计算**，只是材料
- 有哪几条担心被你**退回**变成了要求（这是本技能的产出之一，往往比评语本身有用）
- 有哪些要求是"问了也算不出来"的，为什么

## 绝对不要做

- 不要写分数、等级、星级
- 不要下"推荐 / 不推荐"的结论（那是第 5 步的活）
- 不要把能落成要求的担心留在评语里（那等于放弃了让它被检验的机会）
- 不要只写 `heard` 不写 `basis`
