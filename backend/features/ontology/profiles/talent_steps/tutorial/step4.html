What we add

The link from the candidate box to the skill box

:hasSkill  a  owl:ObjectProperty ;
    rdfs:domain :Candidate ;
    rdfs:range  :SkillTag .

In plain words

We write down that a candidate can have a skill. The link only points one way: candidates have skills; skills do not have candidates.

Why this is next

We have both boxes; now we connect them.

The skills box is an open list

This link points at a box, not at a fixed set of items. We never write down “the skills are Python, Java, Excel” as the rule. We say: a candidate may have any skill that exists, and the skills themselves arrive later — one at a time, from whatever the CVs actually say.

That matters at scale: on this project 277 CVs mention hundreds of different skills, and nobody could have listed them in advance. The box stays open; the contents are data, not schema.

This is the difference between a list of skills and a kind of skill. The box is a kind; the list inside it grows with the data.

What the reader sees

An arrow from the candidate box to the skill box — defined but unused. Nowhere yet does it say who has which skill. That is step 6, and this gap is deliberate.

Optional technical note

An object property — it points at another thing, not at a number. rdfs:domain is the candidate box; rdfs:range is the skill box.

A naming rule we will need later

Classes and individuals must not share a name

If a concrete skill were called CAD and we also built a category called CAD, the same name would be both a box and something inside a box — and the reasoner would read that as “a thing belonging to itself”. So the categories in step 5 are named differently (Programming, not Python).

“0” and “no rows” are different answers. The first says “there are
          none”; the second says “I have nothing to tell you”. Both are honest — and which one you
          get tells you how far the ontology has been built.

          
Notice what “how many candidates?” is really asking: it counts the
          people in the box. The box itself is described by
          :Candidate a owl:Class — one line, one kind of thing. A box is not one of its
          contents.

          
This is how you know an ontology is not finished: the questions
          you most want to ask are the ones it cannot answer. Each next step unlocks one —
          step 5 makes “who has a skill?” find a skill, step 6 makes it find people.
