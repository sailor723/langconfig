What we add

Two people, and what we know about them

:cand_A  a  :Candidate ;
    rdfs:label         "A — Python, 5 years" ;
    :hasSkill        :Python ;
    :yearsExperience 5 .

:cand_B  a  :Candidate ;
    rdfs:label         "B — Python, 1 year" ;
    :hasSkill        :Python ;
    :yearsExperience 1 .

In plain words

Here are two real candidates from our files.

A knows Python and has been working for 5 years. B knows Python too — but has only been working for 1 year.

Both know the same skill. The only thing that separates them is time on the job — and that is exactly what the rule in step 7 will use.

Why two people, and not one

So there is something to compare. Both know Python; only one clears the experience bar. One person would prove nothing — and when the rule arrives in step 7, we need to watch it reject somebody.

What the reader sees

Two items in the candidate box, each with a skill and a number. The link from step 4 now carries something — this is the first time it is used.

Optional technical note

These are facts — sentences whose subject is a concrete individual. The rdfs:label is a person's name; the reasoner ignores it, but it is what a recruiter sees, so the ontology keeps it.

The rule of the course, in one table

To write “candidate A has the skill Python”, three things must exist at the same time:

#WhatTurtleLayer
1the skill exists :Python a :SkillTag , :Programming .fact
2the verb exists :hasSkill a owl:ObjectProperty ;
domain :Candidate ; range :SkillTag .		rule
3the fact connects them :cand_A a :Candidate ; :hasSkill :Python .fact

The fact's payload must be an individual

:cand_A :hasSkill :Python .      ✅ says WHICH skill
:cand_A :hasSkill :SkillTag .     ❌ only says "has some skill"

Point a fact at a class and you can never tell them apart — and the rule in step 7 cannot fire.

The one query that needs the reasoner

          
Every query above could be answered by looking something up. This one
          cannot:

          
SELECT ?c WHERE { ?c a :matches_SoftwareEngineer }

          
“Which of our candidates qualify as a software engineer?” — and at this
          step, nobody qualifies, and the machine cannot tell us that.

That is the whole arc of this course in one comparison: a query
          finds what was written down; a reasoner works out what must be true — but only
          once there is a rule to work it out from. Step 7 writes the rule, and then A qualifies
          and B does not — without anybody typing A’s name anywhere.
