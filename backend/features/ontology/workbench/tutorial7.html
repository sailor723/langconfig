This is the step's actual news: a new object, not a new table. A table is where an object is stored; the object is :Product — something that exists in the business, has an identity (id) and properties (name, price), and can be counted, grouped and joined on.

columntypemeaning
One foreign key cannot express this: it would give an order a single product. So the link itself needs a row — two FKs that name the two ends, plus the quantity the link carries.

So is the link an object?

In the business sense, no: nobody asks for “the order line with id 4”. It is a link — the connection between an order and a product — that happens to carry a number.
In our TTL it is declared as a class (:OrderLine), because OWL object properties are binary and cannot carry attributes: the only way to hang qty on the relationship is to promote the relationship to something that has identity. That promotion is called reification, and it is a modelling choice with a price and a benefit:
  • cost — the link becomes a thing you can group by, so “revenue by product” is really revenue per line, and a wrong join can fan out rows;
  • benefit — the compiler only needs the same two declared edges it already understands, and qty is reachable without special cases.
The alternative — a plain many-to-many link type with no data of its own — needs no class at all: just the two ends and the join path through the table. Our TTL pays for reification because this link does carry data.
