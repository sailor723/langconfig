Step 5 — premium is a definition, not a column

What is stored

Only customers and what they did. There is no premium column — “premium” is not a fact anybody recorded.

Dana's order is 500. Bob 250, Chen 99.50, Amara 120. The rule will say only Dana qualifies.

The definition (TTL)

loading …
:PremiumCustomer ≡ :Customer ⊓ ∃:placesOrder.(:Order ⊓ (:amount ≥ 500))
The threshold 500 lives here, in the ontology — it is not typed into any SQL statement.

Compile the definition to SQL (lane A)

The gate is a parameter of the DEFINITION. Changing it rewrites the axiom's facet and recompiles — the number is never typed into SQL by hand. Try 300 (adds Bob) or 900 (nobody qualifies).

The compiler turns the axiom into a correlated EXISTS:
        customers joined to orders by the declared FK, with
        amount >= 500. The runtime answer is plain SQL — no reasoner on the
        request path.

      
HermiT is a design-time tool: it validates that this definition is
        consistent and classifies sample instances; the same definition is then compiled for
        execution. This axiom is outside OWL 2 QL, so lane B (Ontop) would silently drop it —
        which is exactly why the compiled lane owns the answer.
